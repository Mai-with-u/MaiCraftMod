# 领域规格：寻死

> 状态：已批准（2026-10-15，第 10 节七项都按建议）。
> 范围：能力 `suicide`（主动寻死），排进里程碑一的“其他”。
> 依据：寻死旧逻辑清单（v0 `dev`，`aa97940c9`，SU-01–SU-77）；战斗与陪伴规格 3.6（寻死经 `survival_needs=off` 关掉生存需求，护甲穿回归寻死能力自身）；03 的 M6、M7；07 第 8 节能力目录。
> 边界：死亡停摆、死亡恢复问题、普通世界 2 秒自动重生、重生后回去捡东西归内核与战斗与生存需求域，本能力只用、不另写一份。
> 说明：第 5 节“位置”都指 v0（`dev` 分支）的文件；v1 按本规格重写，不移植。

## 2 真人怎么做

开着死亡不掉落，离家太远、又饿又找不到吃的，玩家会干脆死一次回出生点或床边。先把盔甲脱下来收进包里（穿着死得慢，还白掉耐久），手上的不死图腾也收起来，不然死不成。然后找最快的死法：旁边有岩浆就跳进去，有够高的悬崖就跳下去；身上带着打火石就原地给自己点把火；实在没有，就去贴仙人掌、往怪堆里站。倒岩浆桶最后才用，因为倒出来的岩浆收不回去。死了点重生，到了床边把盔甲穿回去，接着干活。

关着死亡不掉落时不会这么干：死了东西全掉在原地，跑回来未必赶得上。创造、旁观模式死不了，极限模式死了就没了，都不会这么干。

## 3 新逻辑

### 3.1 流程

```text
0 下达时判断（不进游戏）
    创造、旁观 → NOT_POSSIBLE_HERE（这种模式死不了）
    极限       → NOT_POSSIBLE_HERE（死了不能重生，回不了家）
    死亡不掉落：读得到真实规则（单人、局域网主机）→ 关着 → NOT_POSSIBLE_HERE，开着 → 继续
                读不到（连的是别的服务器）→ 给了 keep_inventory_confirmed=true → 继续；没给 → 见决定 3
    via 指定了自造的死法、身上没有对应物品 → NEED_ITEM
1 收起护具   头→胸→腿→脚逐件取下放进背包；副手的不死图腾放进背包，主手的图腾切到空快捷栏格
             （没空格放进背包）。收不走的（背包满、绑定诅咒、没确认）记下，照样往下做
2 挑死法     分刻扫起点附近已加载的地形，按 3.3 的顺序挑一处
3 走过去     走到站位（M2 站位、M10 步行，按这次目标的许可）；跟怪时远了走过去，走着换目标点
             站在站位那一格上就算走到：脚位和寻路判"已经到了"同一套算法，站在灵魂沙、泥、耕地、土径、半砖、
             楼梯上算方块上面那一格（站进格子、被挤出格子也按这个脚位）。连着两趟走路都是人没挪一格就报完成，
             不再起步：离站位一格以内按走到算，远了按走不到放弃这一处（C）
             被叫先到安全处再停：走过去、跟怪走的路上悬在半空先落地站稳才停，落地报的"已停下"不当成走到了，
             不在半路踏进危险；暂停过后从原地接着走过去；身上有脱下的护甲时先落地再穿回
4 接触       走进岩浆、迈下悬崖、贴着仙人掌推、站到怪跟前；自造的站在选好的格里低头点火或倒岩浆
             接触后 20 秒没再掉血就放弃这一处（掉血不问是谁打的）；摔下去落地还活着也放弃；回到 2 挑下一处
5 死         控制循环停摆，发 character_died，挂死亡恢复问题；普通世界 2 秒没人回答自动点重生
6 穿回护甲   重生后（或没死成、要结束时）按原件把脱下的护甲穿回原部位
7 结束       死过 → done；没死成 → 穿回之后按卡住的原因失败
```

### 3.2 判断死亡不掉落

- 单人世界和局域网主机，集成服务端就在本机：在服务端线程上读 `keepInventory`，读回来之前决定返回“信息不全”先等（F：只有集成服务端读得到真实规则）。
- 连别的服务器时客户端拿不到这条规则（原版不同步），只能靠调用方确认：`keep_inventory_confirmed=true`。单人世界不看这个参数，以读到的真实规则为准，读到关着就不做。
- 只在下达时核对一次。寻死途中改规则的情况不管。

### 3.3 挑死法

六种死法，`via` 的取值同名：

| 死法 | 什么样的地方算 | 怎么接触 |
| --- | --- | --- |
| `lava` 现成岩浆 | 能站的格子旁边一格是岩浆（含流动的），那一格与上面一格没有碰撞 | 走进去停住 |
| `fall` 致死落差 | 能站的格子旁边一格往下能落到地面或虚空，途中没有流体、没有未加载的格子；按当前血量算，脱了护甲摔下去会死（`FallDamage`）；落进虚空也算 | 迈出边缘，开始往下掉就松开前进 |
| `cactus` 仙人掌 | 能站的格子旁边一格是仙人掌 | 一直朝它推（碰撞箱比整格小一圈，贴着推才持续掉血），不拆它 |
| `hostile_mob` 敌对生物 | 起点半径内会主动打人的敌对生物（`EntitySight` 认的敌对）；玩家、中立生物不算 | 跟着它走到 1.5 格内停住，被墙挡住就跳；不打、不举盾、不吃东西 |
| `fire` 随身点火 | 身上有打火石或火焰弹；身边找一格（3.4） | 站进格里低头对脚下点一次 |
| `lava_bucket` 随身倒岩浆 | 身上有岩浆桶；身边找一格（3.4） | 站进格里低头对脚下倒一次 |

- 身上有抗火效果时不选 `lava`、`fire`、`lava_bucket`；有缓降效果时不选 `fall`（F：这些死法在效果下不伤人）。
- 扫描：起点是收完护具后的脚位，起点半径 `radius` 内、上下 12 格；每刻最多看 1024 个站位，不加载新区块；扫完不重扫。生物每次挑的时候重读，跟的是同一只（按 UUID），它死了或不见了就算这处没了。
- 没给 `via` 时按下面的顺序挑，同一档里挑最近的（见决定 1）：

```text
第一档  现成岩浆、致死落差   死得快，几乎不会失手
第二档  随身点火             原地就能点，不用走
第三档  仙人掌、敌对生物     慢，怪还可能走开
第四档  随身倒岩浆           倒出来的岩浆源收不回去，最后才用
```

- 给了 `via` 只用这一种，用完了不换别的（C：LLM 点名的死法，不悄悄换成别的）。
- 挑中的只是“看起来能用”，走不走得到由走路如实回答。放弃过的地方（地形按入口格，生物按 UUID）不再挑。

### 3.4 随身造危险

- 选格：身边水平 8 格（不超过 `radius`）、上下 2 格里最近的一格：格子是空气、头上一格没有碰撞、脚下顶面坚固。点火与倒岩浆都是放方块，过一次放方块检查（`PermissionCheck.blockAllowed`，`PLACE_BLOCK`），只看保护：寻死就是目标，放一格火、倒一格岩浆是手段，`change_blocks=none`（默认）时照做，结果的变化里写在哪放了什么。
- 不烧房子、不淹基地（C）：火向四周 1 格、向下 1 格、向上 4 格会蔓延；岩浆在普通维度流 3 格、超热维度（下界）流 7 格，流经处还会点着 3 格内的可燃物。这片范围里有可燃方块、受保护的格子（`Protection`）或没加载的格子就换一格。
- 动手：走到格中央站定，物品拿到手上，低头对准脚下方块的顶面右键一次（M3）。确认：点火看格里出现过火；倒岩浆看格里出现岩浆或手上变回空桶（`ItemUseAim` 的点火、倒流体确认）。
- 火还烧着、岩浆还在就站着受伤；火灭了、岩浆被冲走了原地再造；物品用完、身上也不着火了就放弃这一格。
- 已经右键出去却没出效果（游戏拒绝或没等到确认）：记进 `unconfirmed`，这种死法不再用，换下一种；不换格反复试（F：原生拒绝如实处理）。
- 还没右键出去就失败（瞄不准、拿不到手上）：同样这种死法不再用，换下一种。瞄准有多久的期限由 M3 的交互动作自己管（实机 142 那种无限循环在这里不会出现：每种死法最多失败一次）。

### 3.5 死、重生与死亡恢复问题

- 死了以后什么都不用本能力做：控制循环停摆，发 `character_died`（带死亡界面上的死因），挂死亡恢复问题（`respawn` / `cancel_goal`）；普通世界 2 秒没人回答就自动点重生。服务器开着立即重生也一样。
- 寻死目标在死亡期间不结束，停在原地；重生后控制循环接着推进它。任务看到重生次数比开始时多了，就知道死过了，转去穿回护甲。死在哪一步都算（收护具时就被怪打死也算死成了）。
- 死亡恢复问题选了 `cancel_goal`：寻死目标被取消，护甲不穿回，结果里列出还在背包里的那几件。
- 重生后回去捡东西（`LostItemsNeed`）照常：死亡不掉落开着时身上没少，不会回去；万一少了（规则其实关着、消失诅咒），穿回护甲时生存需求已恢复，它照常插进来。
- v0 的 `auto_respawn=false`（留在死亡界面等调用方决定）不再有：v1 死亡一律走死亡恢复问题，普通世界 2 秒自动重生。

### 3.6 穿回护甲

- 收护具时记下每件护甲的原件（物品与附魔、耐久等组件）和原部位；图腾只收不记，不放回手上。
- 穿回：等背包内容同步过来（最多 10 秒，F：重生后背包内容晚几刻到），在主背包与快捷栏里找组件完全相同的那一件，穿回原部位。原部位已经有别的装备就不换（C）；同种的另一件不顶替（决定 5）；等满 10 秒还找不到就列为没穿回。
- 什么时候穿：死过重生之后；没死成要失败结束之前；暂停或取消时先穿回再停（决定 4）。被新目标直接替换时来不及穿，结果里列出还在背包里的那几件。

### 3.7 生存需求

- 从收护具到死，寻死任务自己声明关掉生存需求（`SurvivalNeedsOff`）：不吃饭、不睡觉、不自卫、不防摔、不退离边缘、不换气、不补光，否则自卫会去打要靠的怪、防摔会垫水。
- 死过重生以后、穿回护甲时、目标暂停时，生存需求恢复。
- 目标许可里写了 `survival_needs=off` 的，按许可整件事都关。
- 要让任务自己声明，目标外壳问一声手上正在跑的能力任务（决定 2）。

### 3.8 组合了哪些模型

M2 站位与靠近、M10 步行（走到站位、跟着怪走）；M3 瞄准—交互—确认（点火、倒岩浆）；M6、M7（关掉生存需求、放方块的许可与保护）；M8（放弃一处换下一处、试过的办法、提问）；感知（敌对生物、身上效果）；穿卸装备接缝（`GearChanges`）。

本能力自己特有的：挑死法与顺序、自造危险的选格与安全范围、接触的走法（走进、迈出、贴着推、站着挨打）、收护具与按原件穿回、死过的判断。

新写的（`ability.suicide`）：

| 类 | 做什么 |
| --- | --- |
| `SuicideModule` | 规格、参数、下达时判断（模式、死亡不掉落、指定死法缺物品） |
| `SuicideInput` | 任务输入：死法、半径、许可 |
| `SuicideTask` | 阶段：收护具 → 挑死法 → 走过去 → 接触 → 穿回；声明关掉生存需求 |
| `WayToDie` | 六种死法与默认顺序 |
| `DeathSpotFinder` | 纯判断：分刻扫地形，挑一处能死的地方 |
| `CarriedHazards` | 纯判断：自造危险选格与安全范围 |
| `StowedGear` | 收起的护具记账：原件、原部位、收不走的原因 |
| `Live*` | 读世界（地形、效果、规则）、找原件的实现 |

要动别处的：`GoalRunner.survivalNeedsOff` 问一声手上的能力任务（一行，决定 2）；`GearChanges` 加一个“从背包第几格穿”的默认方法（只加，决定 5）；游戏接口层加读集成服务端 `keepInventory`；`ParamNames` 登记 `keep_inventory_confirmed`；`AbilityCatalog` 登记模块。

## 4 能力说明（参数与结果）

不接受 `target`。`permissions` 按 M7：`change_blocks` 只管走过去时能动多少地形，不管点火与倒岩浆（受保护的格照旧不放）；`survival_needs` 不用写，寻死自己会关。

| 参数 | 必填 | 说明 |
| --- | :---: | --- |
| `via` | | 死法：`lava` 现成岩浆 / `fall` 摔得死的落差 / `cactus` 仙人掌 / `hostile_mob` 敌对生物 / `fire` 随身点火 / `lava_bucket` 随身倒岩浆；不给按第 3.3 节的顺序自己挑，给了只用它 |
| `radius` | | 找现成死法的范围（格），4..64，默认 24 |
| `max_seconds` | | 最多花多少秒，10..600，默认 120（死亡停摆、暂停期间不计） |
| `keep_inventory_confirmed` | | 你确认这个服务器开着死亡不掉落（keepInventory）。连别的服务器时必须给 `true`；单人世界以游戏里的真实规则为准，不看它 |

能力说明里写清：只在开着死亡不掉落、想快点回出生点或床边时用；正常回家用 `travel`。

结果：

| 情况 | status | summary 例 | problem |
| --- | --- | --- | --- |
| 死过并重生 | `done` | “死了，在 12, 70, -8 重生；脱下的 4 件护甲穿回了” | — |
| 附近没有能用的死法 | `failed` | “没死成：附近 24 格内没有能用的死法” | `NOT_FOUND`：按死法摊平讲一次（没带打火石；岩浆 3 处走不到；悬崖 1 处摔下去没死……），同死法同原因合并计数 |
| 超时 | `failed` | “没死成：120 秒内没死” | `STUCK` |
| 指定的自造死法没带东西 | `failed` | “没死成：身上没有打火石或火焰弹” | `NEED_ITEM` |
| 模式、规则不对 | `failed` | “不寻死：死亡不掉落关着，死了东西会掉” | `NOT_POSSIBLE_HERE` |
| 取消 | `cancelled` | “寻死：被取消” | — |

- `changes`：取下、穿回的每件护甲，收起的图腾，放下的火与岩浆（`block_placed`），用掉的火焰弹、倒空的岩浆桶。
- `attempts`：放弃的每一处与原因（走不到、20 秒没掉血、摔下去没死、点火没出火），同死法同原因合并计数。
- `unconfirmed`：右键出去没等到确认的点火、倒岩浆。
- `details`：

| 字段 | 含义 |
| --- | --- |
| `way` | 最后用的死法；一处都没挑到为空 |
| `keep_inventory_known_by` | 怎么知道开着死亡不掉落的：`game_rule` 读到真实规则 / `caller_confirmed` 调用方确认 |
| `armor_still_worn` | 没脱下来、带着死的护甲与原因（背包满、绑定诅咒、没确认）；没有为空 |
| `totems_still_held` | 没收起来的不死图腾与原因；没有为空 |
| `armor_not_restored` | 脱下了、没穿回的护甲与原因（原件找不到、原部位有别的、被新目标替换来不及穿）；没有为空 |

## 9 验收

离线（判断类用替身接口，任务用动作替身）：

1. `DeathSpotFinder`：岩浆（含流动）、仙人掌、致死落差能挑出来；6 格小坎、落点有水、途中未加载的列不挑；虚空算；抗火时不挑岩浆、缓降时不挑落差；生物只挑会打人的敌对生物、不挑玩家；按档再取最近；`via` 只给那一种；放弃过的不再挑；扫描分刻、扫完不重扫。
2. `CarriedHazards`：可燃方块在火的范围内换格、在岩浆范围内不倒、火够不着时照点；下界岩浆范围更大；受保护格、未加载格在范围内换格；放的那格受保护不选格；没带物品不造。
3. `SuicideModule`：创造、旁观、极限 NOT_POSSIBLE_HERE；读到关着 NOT_POSSIBLE_HERE；规则还没读回来先等；多人没确认按决定 3；确认了照做；`via=fire` 没带 NEED_ITEM。
4. `SuicideTask`：四件护甲加副手图腾收好 → 挑岩浆 → 走过去 → 进岩浆 → 重生次数加一 → 按原件穿回（背包里两顶铁头盔穿回原来那顶）→ done；背包满护甲脱不下照样往下做并列出；附近没死法 → 穿回后 NOT_FOUND，原因按死法摊平；摔下去没死 → 换下一处；20 秒没掉血 → 换下一处；点火右键出去没出火 → 记 `unconfirmed` 换下一种；瞄不准 → 换下一种，不无限循环（实机 142）；取消 → 先穿回再按取消结束；暂停 → 先穿回，恢复后重新收；死亡恢复选 `cancel_goal` → 结果列出没穿回的护甲；收护具时就死了也算 done。
5. 生存需求：尝试期间关、重生后与穿回时开、目标暂停时开（`GoalRunner` 问手上的任务的测试）。
6. 最坏情况的结果长度：30 处岩浆都走不到、自造两种都失败时，`attempts` 与 `problem.message` 按死法和原因合并，长度有界。
7. 接口快照（新能力、新参数名）、架构检查。
8. 先到安全处再停：走过去悬在半空被叫先停稳 → 落地才算停稳，落地不当成走到、不踏进危险；暂停过后从原地重新走过去；身上有脱下的护甲时先落地、再穿回才算停稳。跟怪走的那一趟要真客户端，实机里看。
9. 走到站位：读出来的脚位比站位低一格（站在灵魂沙上）照样去接触危险；走路一出发就报完成、人没挪动，每个站位起步两趟就停，远了按走不到放弃，不无限起步。站在灵魂沙、泥、耕地、土径、下半砖上的脚位是上面那一格（寻路脚位的测试）。

实机（测试 Agent；本会话不跑）：

1. 单人、开着死亡不掉落、旁边有岩浆湖：不给 `via` → 脱甲收图腾 → 走进岩浆 → 2 秒自动重生 → 床边穿回护甲，结果 done。
2. 洞里没有现成危险、身上有打火石：原地点火烧死（10-05 外部用户报告的场景）。
3. 沙漠平地只有仙人掌：贴着仙人掌死（`030477fa6` 的场景）。
4. 旁边有 6 格小坎和 30 格悬崖：只跳悬崖。
5. 夜里有僵尸、`via=hostile_mob`：走过去站着挨打，不还手、不举盾。
6. 背包满：护甲脱不下，照样寻死，结果写明带着死的护甲。
7. keepInventory 关着：不做；连别的服务器没给确认：按决定 3。
8. 点火瞄不准（实机 142）：换下一种或如实结束，不无限循环。
9. 寻死途中取消：先穿回护甲再结束。
10. 走向岩浆或跟着僵尸、正跳过一道坎时暂停目标 → 落地站稳才停，不在半空松手、不在半路踏进去；恢复后接着走过去。
11. 下界灵魂沙峡谷：站位在灵魂沙上，走到就去接触危险，不原地反复起步；身上有打火石时站在灵魂沙上原地点火能站进格子。

## 10 待定

**已定（2026-10-15）**：七项都按建议批准。

1. **auto 的顺序**。建议按第 3.3 节分档：岩浆与致死落差 → 随身点火 → 仙人掌与敌对生物 → 岩浆桶。另两种：照 v0（现成的最近的先，都没有才点火，最后岩浆桶）；或照你 10-05 原话“auto 优先点火”理解成身上有打火石就先点火、再现成的、最后岩浆桶。
2. **生存需求怎么关**。建议寻死任务自己声明（3.7）：`GoalRunner.survivalNeedsOff` 在目标跑着时多问一声手上的能力任务，改内核一行；重生后、穿回时、暂停时生存需求恢复。另一种是要求调用方写 `permissions.survival_needs=off`，不写就提问——多一轮来回，而且重生后也一直关着。顺带：现在许可写了 `off` 的目标暂停时生存需求也还关着，和战斗与陪伴规格 3.6“暂停后恢复”不符，要不要同一行一起改成暂停时恢复？
3. **连别的服务器、没给 `keep_inventory_confirmed`**。建议提问 NEED_APPROVAL：“这个服务器开着死亡不掉落吗？”选项“开着，继续寻死” / “没开，不做了”，答了就按答的办，不用重下。另一种照 v0 直接失败，叫带上参数重下。服务器也装了 MaiCraft 时经服务端联动读真实规则，这次先不做。
4. **暂停、取消时护甲**。建议都先穿回再停（像人不打算马上死了先把甲穿上），恢复后重新收；被新目标直接替换时来不及，结果里列出。另一种照 v0：暂停不穿，取消后才穿。
5. **按原件穿回**。建议照 v0 只穿原来那一件（附魔、耐久一样），要给穿卸装备接缝加一个“从背包第几格穿”的默认方法（只加不改）。另一种只按物品种类穿，背包里有两顶铁头盔时可能穿成另一顶。
6. **坠落只选摔得死的**。建议只选按当前血量、不穿护甲摔得死的落差，虚空也算；v0 是落差 ≥ 6 格就选，摔不死再换下一处。
7. **名字**。参数沿用参数名表的 `via`、`radius`、`max_seconds`，新登记 `keep_inventory_confirmed`；敌对生物这种死法叫 `hostile_mob`（单写 `mob` 会被读成包括猪牛羊）。

> 状态：已批准（2026-11-05，11.6 四件都按建议）。
> 用户原话：「游戏嘛，开心最重要，所以如果死亡不掉落开的话，我甚至鼓励使用/suicide，这样各种回家回满血满饱食度就很方便了（如果当前位置或进度不重要的话）」「有时候保持活着不一定是对的」。
> 批准范围：11.2 的命令死法由用户这两句话批准；11.3 到 11.5 按本节送审。
> 边界：Mod 自己的生存需求（饿了吃东西、着火自救、卡坑脱困）不会自己去寻死。位置和进度要不要紧由 LLM 判断，Mod 只负责把这条路和它的条件说清楚。

### 11.1 真人怎么做

服务器给了 `/suicide`，或者自己有 `/kill` 的权限，玩家直接敲命令，一下就死。不用找岩浆、悬崖，也不用脱甲：死亡不掉落开着，护甲本来就不掉，`/kill` 也不磨护甲。命令不管用（没权限、插件要二次确认）才去找别的死法。

死亡不掉落开着时，饿得没吃的、卡在坑里、困在水里、离家太远，只要这里的位置和手头的活不要紧，死一次回床边，血和饱食度都是满的，比硬撑着省事。

### 11.2 命令死法 `command`

```text
档位      第零档，比现成岩浆、致死落差还先：死得最快，不用走路，不放火不倒岩浆
用哪条    客户端收到的命令树里有 suicide → 发 /suicide；
          没有 suicide、有 kill → 发 /kill @s；
          两条都没有 → 这一档没有，不给 via 时照第 3.3 节的六种挑。
          服务器只把角色有权限用的命令发给客户端，所以树里有就是能用（F）
护甲      用命令死不脱。/kill 的伤害类型 generic_kill 在 bypasses_armor 里，护甲不吸收、不掉耐久；
          死亡不掉落开着，护甲本来不掉。脱甲的两条理由（死得慢、白掉耐久）都不成立
图腾      /kill 不收：generic_kill 在 bypasses_invulnerability 里，原版判定图腾时第一句就是这类伤害不救（F，1.21.1 核对过）。
          /suicide 是插件给的，核对不了它怎么杀，先收图腾（收法同 3.1 第 1 步），收不走照样发
发了以后  只发一次。100 刻（5 秒）内重生次数涨了（或进了死亡停摆）就是死成了，往下照 3.5、3.6 走。
          5 秒没死就当这种死法不管用：这 5 秒里服务器在聊天栏回的话写进 attempts
          （"发了 /suicide，5 秒没死；服务器回：……"），然后照原流程脱甲、收图腾、挑六种。
          不换写法重发：不再试 /minecraft:kill，不替插件补 confirm
许可      发命令不动方块，change_blocks 不管它；能不能用由服务器按角色的权限裁决
实例配置  不受"允许执行游戏命令"（allowGameCommands）限制，见 11.6 第 1 条
via       新取值 command：只用命令。命令树里两条都没有 → 下达时 NOT_POSSIBLE_HERE
          （"这个服务器没给角色能用的寻死命令"）；发了 5 秒没死 → 不换别的死法，按卡住失败（STUCK），problem 带上服务器回的话
```

- 死亡不掉落与模式的判断不变：单人读游戏规则，别人的服务器要调用方确认（3.2）。关着、创造、旁观、极限都不做，命令死法同样先过这一关。
- 单人世界没开作弊：命令树里没有 kill，自然走原来的六种。
- 结果：`details.way` 多一个取值 `command`，另加 `details.command`，写发的是哪条（`/suicide` 或 `/kill @s`）。`changes` 里没有脱甲；`/suicide` 前收的图腾照样记。

### 11.3 `observe(self)`：死亡不掉落开没开、重生在哪

LLM 平时看着饱食度、血和这两项，自己决定要不要寻死回家：饿得没吃的时是提前寻死，还是去拿别人家的（物资规格第 22 节，那条事件拿完才发，来不及改主意）。

`keep_inventory`：死亡不掉落开没开，`on` / `off` / `unknown`。

- 单人世界、局域网主机读游戏规则，得 `on` 或 `off`；规则还没读回来的那一会儿不带这一项。
- 连别人的服务器读不到，得 `unknown`。调用方确认过的（给过 `keep_inventory_confirmed=true`）不记，下次照样是 `unknown`。
- 寻死结果里原来叫 `details.keep_inventory` 的那一项（这次是怎么知道它开着的：`game_rule` / `caller_confirmed`）改名 `details.keep_inventory_known_by`：同一个名字在两处取不同的值，只看名字会拿错。改名随实现一起做，07、随包说明的"结果怎么读"、CHANGELOG 同步，CHANGELOG 写明旧名改成了什么。

`respawn`：死一次会回到哪儿。

| 字段 | 意思 |
| --- | --- |
| `x`、`y`、`z`、`dimension` | 重生的地方 |
| `source` | `bed` 床 / `respawn_anchor` 重生锚 / `world_spawn` 世界出生点 |
| `confirmed` | `true`：单人世界、局域网主机，在服务端线程读到的这个角色设下的重生点；`false`：别人的服务器不告诉客户端，是推断 |

- 单人、局域网主机：读角色设下的重生点。没设过，或者设下的那格现在不是床、重生锚没充能，就是世界出生点。
- 别人的服务器：报角色最近一次睡过的床（世界记忆里记着），`source=bed`、`confirmed=false`，床被拆或被挡住就会回世界出生点。没睡过就报世界出生点（客户端知道），`confirmed=false`。插件改了重生规则的服务器，以实际为准。
- 刚进世界、什么都读不到时不带这一项。

### 11.4 随包说明 `suicide.md`

"用途"改宽：

- 死亡不掉落开着时，寻死是正常手段：一次回到重生点（床边、重生锚，没有就是世界出生点，看 `observe(self)` 的 `respawn`），血和饱食度都是满的。
- 位置和手头进度不要紧时用。不要紧指：不在施工半路，附近没有要捡的东西，不是在远处干到一半的活。这时比硬撑着找吃的、慢慢回血、费劲脱困、从远处走回家都省事。
- 死亡不掉落关着时不用：死了东西全掉在原地。正常回家用 `travel`。

"怎样算完成"开头加一条：命令树里有 `/suicide` 或 `/kill` 就先发命令，不脱甲；5 秒没死再脱甲找别的死法。`via` 和 `details.way` 的取值加上 `command`。

### 11.5 走投无路时提一句寻死

下面四处没做成时，在给 LLM 的建议末尾接一句寻死。只改文字，不改问题种类，也不改流程：

| 哪里 | 接在哪 |
| --- | --- |
| 卡坑脱困升到头还出不去；`change_blocks=none` 不升许可、原样按走不通收场的也算 | 走不通那条 `problem.suggestion`（none 时接在实际报走不通的那一处） |
| 饿了，问遍各处都弄不到吃的 | 那条 `need_unhandled` 事件的消息末尾（事件没有建议字段） |
| 水里从这里到不了（呼吸预算放弃这段路） | 走不通那条 `problem.suggestion` |
| 点名战斗撤离、回不了血 | 现在那句"又开着死亡不掉落时，也可以 suicide 回出生点重置"换成同一份 |

说法：

```text
读到开着          死亡不掉落开着，位置不要紧的话可以 suicide 回重生点，血和饱食度都是满的
读不到（别人的服务器）  如果这个服务器开着死亡不掉落，位置不要紧的话可以 suicide（带 keep_inventory_confirmed=true）回重生点，血和饱食度都是满的
关着；创造、旁观、极限；规则还在读   不提
```

这句话由一处判断给出，四个地方都用它。第四处是战斗撤离里已有的那句，现在是第二个调用方，所以一起下沉，不各写一份。

### 11.8 验收

**离线**：

1. `DeathCommands` 与发命令阶段：命令树有 suicide 发 `/suicide`；只有 kill 发 `/kill @s`；两条都没有这一档就没有。只发一次。5 秒内重生算死成；5 秒没死，服务器回话写进 attempts，转去脱甲、挑六种。
2. `SuicideTask`：命令死不脱甲；`/kill` 不收图腾，`/suicide` 收图腾。`via=command` 时：命令树里两条都没有，下达就 NOT_POSSIBLE_HERE；发了没死，按 STUCK 失败、带回话，不换别的死法。
3. `SuicideWayOut`：开着、读不到、关着、创造、旁观、极限、还在读，七种各说对或不说；四处调用方的建议或事件消息末尾带上这一句。
4. `respawn`：单人读到床、重生锚、没设过、床没了四种；别人的服务器有睡过的床、没睡过两种。
5. `keep_inventory`：单人开着 `on`、关着 `off`、还在读不带；别人的服务器 `unknown`，给过确认也还是 `unknown`。
6. 接口快照（`via` 新取值、`observe(self)` 新字段）、架构检查。

**实机**（还没跑）：

1. 单人开作弊、死亡不掉落开着：`suicide` 不给 `via`，发 `/kill @s` 一下就死，不脱甲，重生后 done，`way=command`。
2. 单人不开作弊：走原来的死法。
3. 装了带 `/suicide` 插件的服务器、给了 `keep_inventory_confirmed=true`：发 `/suicide` 死成。
4. 卡坑脱困失败、死亡不掉落开着：走不通的建议末尾有那句寻死；关着时没有。
