## 2 真人怎么玩

进服拿到一张魂符，对着地面一点，冒出一只已经认自己做主人的女仆，是哪个角色要看运气（酒狐的几种皮肤约占一成多）。走近她看看头顶的作息和好感，拿蛋糕她会跑过来仰头乞食；潜行右键让她坐下，拿金苹果潜行右键喂她，拿鞍右键把她抱起来。对着她按聊天键打开对话框说话，她头上冒"少女思考中"，然后回一句话，也会照着话去坐下、跟上、换工作。空手右键打开她的界面，点皮肤按钮换成酒狐，点任务按钮让她去割草、种地，把锄头放进她的主手、种子放进她的背包。闲下来摆一张五子棋盘，她会坐到对面陪着下。她死了，聊天栏会出现一行坐标，去那里右键墓碑把东西拿回来。

## 3 新逻辑

### 3.1 认出女仆（1a）

联动实现 `ModSight`，每次场景刷新时把区域里的女仆与女仆墓碑交出去，身份按实体编号（`ModThing.Identity.ENTITY`），和原版实体共用同一个 e#。场景里那一只生物仍照常出现在 `entities`，`mod_things` 只多给她的女仆状态。

`maid`（场景里给 `summary`，`observe(detail)` 给全）：

| 字段 | 读自 | 说明 |
| --- | --- | --- |
| `skin_id` | `EntityMaid.getModelId()` | 皮肤（模型）ID，例如 `geckolib:winefox` |
| `skin_name` | 本机模型表里这个 ID 的显示名 | 随客户端语言；本机模型表里没有时不给 |
| `work` | `getTask().getUid()` | 工作 ID，例如 `touhou_little_maid:farm` |
| `work_name` | 工作的显示名 | |
| `work_shift` | `getSchedule()` | `day` 白班 / `night` 夜班 / `all` 全天 |
| `shift_now` | `getScheduleDetail()` | `work` 工作中 / `rest` 休息 / `sleep` 睡觉；TLM 自己按班次与客户端世界时刻算好的此刻活动（`WORK` / `IDLE` / `REST`），Jade 显示的也是它：白班 6–18 点工作、18–22 点休息、其余睡觉；夜班 18–6 点工作、6–14 点睡觉、14–18 点休息；全天恒为工作。不另抄一份时段表 |
| `stay` | `isHomeModeEnable()`、`getRestrictCenter()`、`getRestrictRadius()` | 跟随时 `{"mode":"with_you"}`；驻守时 `{"mode":"in_area","center":[x,y,z],"radius":r}` |
| `pickup` | `isPickup()` | 布尔 |
| `affection` | `getFavorability()` | `{"level":等级,"points":点数,"to_next":还差几点}`；等级按 64/192/384 分档（0–3 级，满级 `to_next` 不给），写成纯函数 |
| `begging` | `isBegging()` | 只在为 true 时给 |
| `invulnerable` | `getIsInvulnerable()` | 只在为 true 时给 |
| `thinking` | 气泡集合里有没有等待气泡 | 只在有时给：`{"note": 副文本}`，副文本是她在调哪个工具 |
| `bubbles`（二期） | 气泡集合里的文字气泡 | 文字列表，见第 3.8 节 |

`detail` 另给 `rideable`、`backpack`（背包种类 ID）、`experience`（经验点）。

`maid_tombstone`：女仆墓碑，`summary` 给 `maid_name`（墓碑上的女仆名）。墓碑不是活体，不进 `entities` 的血量。

驯服关系、坐没坐、血量、手持与盔甲不在这里重复：它们是原版生物事实，走场景实体的 `traits` 与字段（M7 的"驯服"、"坐着"）。

### 3.2 对她说话（1a）

`chat(target=e#, message=…)` 经说话办法 `TalkTo` 找到能听这只生物说话的实现。女仆的实现流程：

```text
认她：目标是 TLM 女仆；不是自己的女仆 → NOT_POSSIBLE_HERE（F：TLM 只对主人开对话，真人对别人的女仆按聊天键什么都不会发生）
她还在想上一句（头上有等待气泡）→ 先等到等待气泡消失，最多等 max_seconds；等满按 reply_pending 收场，不叠着发（C：TLM 不限并发，叠着发会同时出几份回话、顺序不定）
走近并对准她 → 提交一次打开对话框的包 OpenMaidAIChatPacket（交互与容器规格第 11.6 节"对准生物发一次模组的包"）
等对话框弹出（读写端认 AIChatScreen）；40 刻内没弹出 → unconfirmed 收场，问题写明对话框没开（服务器关了 AI 对话、她已经不是你的、网络延迟都可能）
对话框开了先等 6 刻（TLM 在开框后 5 刻内吞字）
逐字打字：复用 TypeChatDraft，草稿接缝由联动实现（把新长出来的字用原版 Screen.charTyped 打进对话框），节奏与公屏打字相同
回车：原版 Screen.keyPressed(GLFW_KEY_ENTER)；对话框自己发 SendUserChatPackage 并关上
认听到：对话框关上，且 40 刻内她头上冒出等待气泡或新的文字气泡 → delivered=true；都没有 → unconfirmed，不重发
等回话：见下
```

打字途中被生存需求打断：关掉对话框，回来重新对准、重新开框、从头打（对话框重开后输入框是空的）。目标被取消时关掉自己开的对话框。

认领回话：

- 从回车那一刻起，取聊天栏新收到的服务端系统消息。TLM 在她头上换上文字气泡的同时，把回话以灰字 `<女仆名> 文本` 只发给主人（名字是服务端的 `getName()`：有自定义名用自定义名，否则是服务端模型表里皮肤的名字）。第一条以 `<她的名字> ` 开头的系统消息就是回话，去掉前缀写进 `reply`。她的名字按两个候选比：她此刻在客户端的显示名、本机模型表里她皮肤的显示名；两个都对不上（服务端与本机的模型名翻译不同）而角色只有她一只在想时，`<任意名字> 文本` 形式、名字不是角色自己的那条也认作她的回话。对话框回车时 TLM 在本机聊天栏回显 `<角色名> 原话`，这一行不经服务端，不会被当成回话。
- 两只同名女仆同时在想时，按"谁的等待气泡刚消失"认领；分不清就把两条都放进 `notices`，`reply` 不给，`reply_pending=false`，问题写明有同名女仆分不清是谁说的。
- "角色设定文件已经自动生成完毕"这一句（TLM 首次和没有预设人设的女仆聊天时只生成人设、不回答这一句）单独认领：`reply` 不给，`persona_generated=true`，结果写明她这次只生成了人设、没回答，要再说一遍。
- 同一窗口里其他新的系统消息原话放进 `notices`（站点没配好、对话被禁用、token 用完这类 TLM 提示，都是红字系统消息）；有这类提示且没有回话时，问题种类 `REFUSED_BY_GAME`，附原话。
- 等待以 `max_seconds` 为上限（默认 30，最多 90，这是角色愿意站着等多久，不是 TLM 的上限：她每调一次工具等待气泡都会续期，一句话最多 16 轮工具，开着网络朗读时还要等音频回来才发回话）。等待气泡消失后再等 20 刻收不到回话，就按 `reply_pending=true` 收场；等满也一样。之后的回话照常以 `kind=system` 进 `events(topic=chat)`，`chat` 不重发。
- 她用自带工具改了自己的状态（坐下、跟随或驻守、班次、工作）：说话前后各读一次 `maid` 的同名字段，变了的按 `ENTITY_AFFECTED` 变化列出（"她自己改成了驻守"），她的提示词不让她口头播报工具结果，所以只能这样确认。

说话不进公屏，也不打开原版聊天框。对话框是她的界面，观众在画面上看到的是角色看着她、开框、打字。

### 3.4 `maid_configure`（1b、二期）

改一只女仆的设置。`target` 是她的 e#，`settings` 是 JSON 对象，键是女仆认的设置项，值写字符串。按给的顺序一项项改，每项确认了再改下一项；已经是目标值的直接算完成，不打开界面也不发包。

| 键 | 取值 | 怎么改 | 怎么确认 | 期 |
| --- | --- | --- | --- | --- |
| `skin` | 皮肤 ID | 界面开着时发 `MaidModelPackage` | `skin_id` 变成它 | 1b |
| `work` | 工作 ID（可省命名空间 `touhou_little_maid:`） | 发 `MaidTaskPackage` | `work` 变成它 | 1b |
| `work_shift` | `day` / `night` / `all` | 发 `MaidConfigPackage`，四个字段带齐、只改班次 | `work_shift` | 1b |
| `stay` | `with_you` 跟着 / `in_area` 待在活动范围里 | 同上，只改驻守 | `stay.mode` | 1b |
| `pickup` | `true` / `false` | 同上，只改拾取 | `pickup` | 1b |
| `mainhand`、`offhand`、`head`、`chest`、`legs`、`feet` | 物品 ID 或标签；空字符串表示拿回角色背包 | 界面开着时把那件从角色背包点进她对应的装备格（主手第 40 格、副手第 41 格、头胸腿脚第 36–39 格）；格里原有的东西换回角色背包 | 她那一格变成它（原版同步的手持与盔甲） | 二期 |

流程：

```text
目标不是女仆（读写端认不出）→ NOT_POSSIBLE_HERE
所有项都已是目标值 → 直接完成
有要开界面的项 → 用交互与容器规格第 11.4 节"点开生物身上的界面"打开她的主界面（空手右键、等布局认出）
  她在睡觉 → 界面打不开（TLM 不给睡着的女仆开界面）→ REFUSED_BY_GAME，写明她在睡觉，等她醒了再改
逐项：发包或点格子 → 等同步字段变成目标值（每项最多 40 刻）
  变了 → 记一条 ENTITY_AFFECTED 变化
  聊天栏冒出回应（例如服务器关了换皮肤）→ REFUSED_BY_GAME 附原话，停在这一项
  弹出日程点确认屏（开驻守时日程点离她超过 32 格或不在同一维度，TLM 弹 CheckSchedulePosGui 拒绝）→ 关掉它，REFUSED_BY_GAME，写明原因
  等满没变 → unconfirmed，停在这一项
关上界面
```

- `skin` 取值不在本机模型表里：`INVALID_PARAMETER`，附三个最相近的 ID（F：真人只能从界面的列表里挑）。值里只有"酒狐"这类中文名时也一样按不认识处理，技能里列出酒狐带人设的 19 个 ID。
- `work` 取值不在 TLM 的工作表里：`INVALID_PARAMETER`，附全部工作 ID 与显示名。工作表在客户端可读。
- 切工作不看她手上有没有合适的工具：TLM 允许切，切过去她只会站着不干。结果里附上界面那条启用条件的文字（例如"主手需要锄"），满不满足由 LLM 看。
- 不在工作时段时切了工作她要等班次开始才动，结果写明 `shift_now`。
- `stay=in_area` 的含义：设过日程点时围着日程点（工作时 12 格、休息和睡觉时 6 格），没设过就以她此刻的位置为圆心。
- 装备项：角色背包里没有那件 → `NEED_ITEM`，不替 LLM 去拿（先 `obtain`）；她的格子不收（盔甲槽只收能穿的）→ 界面点不进去，按 `REFUSED_BY_GAME` 交回。
- 坐下不在这里：坐下只走 `use(sneak=true)`。
- 改别人的女仆：界面打不开（TLM 只给主人开），如实按 `REFUSED_BY_GAME` 交回，不预先拦。

结果细节：`applied`（每项 `key`、`from`、`to`）、`skipped`（已是目标值的项）、`work_hint`（切了工作时的启用条件文字）、`shift_now`。

### 3.5 女仆界面的布局证明（1b）

`registry.menuLayout(this, 证明)` 证明这 8 种菜单：`touhou_little_maid:maid_empty_backpack_container`、`maid_small_backpack_container`、`maid_middle_backpack_container`、`maid_big_backpack_container`、`maid_crafting_table_backpack_container`、`maid_ender_chest_container`、`maid_furnace_container`、`maid_tank_container`（`T:init/InitContainer.java`）。

| 菜单槽号 | 内容 | 证明里算 |
| --- | --- | --- |
| 0–26、27–35 | 角色背包、快捷栏 | 角色侧（恰好 36 格） |
| 36–39 | 她的盔甲 | 不列进容器侧；装备项按槽号直接点 |
| 40、41 | 她的主手、副手 | 同上 |
| 42–47 | 她的内置 6 格 | 容器侧 |
| 48 | 与 47 同一格的展示位 | 不列 |
| 49 起 | 背包扩展：小 6 格、中 18 格、大 30 格；工作台、熔炉、储罐背包 12 格 | 容器侧，只列储物格 |
| 工作台、熔炉、储罐背包的功能格 | 合成格、产物、燃料、流体进出 | 不列 |
| 末影箱背包 49–75 | 角色自己的末影箱 | 不列（那是角色的东西，不是她的） |

证明按菜单类型注册 ID 认，槽号以实际菜单的 `slots` 为准：联动先核对角色侧那 36 格确实是角色背包、每个容器侧槽的 `container` 是她的物品栏，形状对不上就交 `Unsupported` 并说明哪里对不上，一格都不点。

### 3.6 存取她的东西（二期）

`deposit(target=e#)` 往她背包里存：走交互与容器规格第 11.7 节"实体身上的储物"，打开她的界面后照容器的规矩逐笔搬，只动容器侧那些格（内置 6 格与背包扩展的储物格），不碰她手上和身上的。只在点名她时才这样做：自动挑存放处时不把女仆算进去。往别人的女仆身上存：界面打不开，如实交回。

从她背包里往外拿这次不做（原因见交互与容器规格第 11.7 节：`obtain` 不带 `target`）；`use` 空手点开她的界面能列出里面有什么，她手上和身上的东西用 `maid_configure` 的装备项拿回。

### 3.7 五子棋（二期）

TLM 的五子棋盘占 3×3 个方块位置（中心一整格加四周各半格，看上去 2×2 格大、2 像素高），15×15 路。玩家执黑先手，女仆执白后手；女仆要坐在棋盘边的座位上才开得了局；她那一手由下棋玩家自己的客户端算好、停 0.25–1.5 秒再发给服务器（`GomokuClientPackage` → `GomokuServerPackage`），角色的客户端装着 TLM，会自动替她应答。

几何（全部读自方块状态与源码常量，写成纯函数）：棋盘数组 `chess[x][y]` 的 x 沿世界 +X、y 沿世界 +Z，与棋盘朝向无关；每路交叉点能点中的是顶面上 0.07 格见方的一小块（三段各自的起点不同：靠 −X/−Z 那半格从 0.54 起、中心格 X 从 0.08 起 Z 从 0.07 起、靠 +X/+Z 那半格从 −0.01 或 0 起，路距 0.1316）。她的座位在中心格朝 `FACING` 顺时针转一格的方向 1.5 格处，玩家这一侧是它的对面。棋盒（点它重开）随朝向的轴在两个角上的一块里。

观察：`mod_things` 新种类 `gomoku_board`，按棋盘中心那格领 b#。`summary`：`turn`（`you` 轮到你 / `maid` 轮到她 / `over` 已结束）、`moves`（已下几手）、`last_move`（最后一手，记谱写法见下）、`maid_seated`（座位上有没有坐着女仆）、结束时 `winner`（`you` / `maid` / `draw` 和棋；TLM 只记"有人赢了"，谁赢看最后一手是谁下的）。`detail` 加 `board`：15 行，每行 15 个字符，`X` 是你（黑）、`O` 是她（白）、`.` 是空，第一行是第 15 路。

记谱：列用字母 A–O（站在玩家这一侧面朝她看，从左到右），行用数字 1–15（离玩家最近的是 1），例如 `H8` 是天元。记谱与数组下标的换算按她座位的方向转，写成纯函数。

能力 `gomoku_play`：

| 参数 | 必填 | 说明 |
| --- | :---: | --- |
| `target` | ✅ | 棋盘的 b# |
| `move` | 落子时 ✅ | 这一手下在哪：记谱写法，例如 `H8` |
| `operation` | | `move` 落子（默认）/ `reset` 重开一局（点棋盘角上的棋盒） |
| `max_seconds` | | 落子后等她应手最多几秒，默认 15，最多 30 |

```text
走到棋盘玩家那一侧，站到够得着的地方
落子：对准那一路交叉点（每个点能点中的范围只有 0.07 格见方）空手右键
  确认：这一格变成 X（方块实体同步）；10 刻内没变 → 看聊天栏回应：没有女仆、不是你的女仆、不轮到你这类 TLM 原话 → REFUSED_BY_GAME；什么都没有 → unconfirmed
  这一格已经有子 → INVALID_PARAMETER（F：棋盘上看得见那格有子）
等她应手：board 里多了一颗 O，或 turn 变回 you，或 over；等满 max_seconds 没应 → 结果写明她还没下（reply_pending=true），不算失败
重开：对准棋盒右键，确认 moves 归零
```

结果细节：`your_move`、`maid_move`（她下在哪，没下给空）、`board`、`turn`、`winner`。赢了以后她的好感涨多少、段位升没升由 TLM 结算，结果不推测，LLM 看 `maid` 的 `affection` 与聊天栏。

女仆怎么坐上棋盘：休息时段她自己会去附近的空棋盘坐下；工作时段要把她的工作切成 `board_games`。这写进技能，不在能力里替 LLM 安排。

### 3.8 气泡正文（二期）

`maid.bubbles`：她头上此刻的文字气泡，按出现先后列文字（最多 5 条）。读法：TLM 的气泡集合在同步实体数据里，文字气泡的正文字段没有读法，但它的序列化器是公开的——读写端把那条气泡用 `ChatBubbleRegister` 里登记的序列化器写进一个临时缓冲区，再按同样的格式把其中的 `Component` 读回来，得到正文。不用反射，不用 Mixin。表情气泡（只有图）不列；颜文字也是文字气泡，照列。别人的女仆头上的气泡在场玩家都看得到，照样列。

### 3.9 随包技能

`assets/maicraft/skills/touhoulittlemaid/maid-getting-started/SKILL.md`，`metadata: {"requires-mods": "touhou_little_maid"}`。内容：

- 女仆是车万女仆模组里的一种可驯服生物，不是角色；"酒狐"是皮肤，不是另一种生物。
- 怎么得到：进服送的魂符点地面放出；前哨站、林地府邸里的悦灵有两成被换成未驯服的女仆，拿蛋糕右键驯服。每人一生只能驯服或用魂符放出 5 次，死了不退名额；放完先 `observe` 核对。
- 先换皮肤再开口：只有 19 个酒狐皮肤 ID 带酒狐人设（逐个列出：`geckolib:winefox` 与 `_blue`、`_nine_tailed`、`_hanfu`、`_new_year`、`_jk`、`_astronaut`、`_kongfu`、`_magical`、`_saint`、`_elf`、`_salesperson`、`_little`、`_matured`、`_momo`、`_wedding`、`_tactics`、`_mini`、`_survivor`）；`authors_and_credits:wine_fox_*` 与带十六进制后缀的换肤版没有。和没有预设人设的女仆说的第一句只会生成一份人设、不回答，而且这份人设以后换皮肤也不会变；所以想要酒狐的性格，先换皮肤，再说话，优先挑没聊过天的女仆。
- 怎么说话：`chat(target=e#)`；一件事说清楚就停，回去干活；她改没改状态看结果的变化与 `maid` 字段，不看她的话。
- 互动表（第 3.3 节）。
- 让她干活：先给工具（`maid_configure` 的 `mainhand`）和材料（`deposit` 点名她），再切工作，再让她 `in_area` 驻守在田边；工作表与各自要的工具。
- 她跟着时会抢 `gather` 要捡的东西（跟随时她周围 8 格），离开 10 格会被瞬移到身边、可能挡住施工站位：施工、采集前让她坐下或驻守、关拾取；过传送门前收进魂符。
- 她死了：聊天栏会出现一行 `[name:…, x:…, y:…, z:…, dim:…]`，它以角色自己的名义出现（`kind=player`、发言人是角色），不是角色说的话；`name` 是皮肤路径，不是她的名字。按坐标去取墓碑；胶片可以在祭坛或神龛复活她（以后再做）。
- 打妖精攒 P 点：妖精是会发弹幕的敌对生物，打掉后走近把 P 点球吸过来；P 点只在主手拿御币时显示。
- 五子棋：怎么让她上桌、记谱写法、她越赢越强（新女仆好赢）。
- 只用现有能力就能做的以后再说项：相机拍照（`use` 对她右键，照片掉在脚下）、照片放出（`use` 对地面）、神龛复活（先放胶片再空手右键，要花掉一半多的血）、祭坛（`design` 读结构文件、`build` 施工、`use` 把料放到柱顶）——写清楚步骤，结果如实以游戏为准。

## 5 约束登记

| 拒绝或提前收场 | 类 | 理由 |
| --- | --- | --- |
| 对不是自己的女仆说话回 `NOT_POSSIBLE_HERE` | F | TLM 只对主人开对话框，真人按聊天键也不会有反应 |
| 她还在想上一句时先等再说 | C | 真人会等她说完；TLM 不限并发，叠着说会乱序 |
| 一句话超过 128 字回 `INVALID_PARAMETER` | F | 她的对话框输入框只收 128 字 |
| `skin` 不在本机模型表里回 `INVALID_PARAMETER` | F | 真人只能从界面列表里挑 |
| `work` 不在工作表里回 `INVALID_PARAMETER` | F | 同上 |
| 五子棋那一格已有子回 `INVALID_PARAMETER` | F | 棋盘上看得见 |
| 装备项角色背包里没有那件回 `NEED_ITEM` | F | 手里没有放不进去 |

不拦的：切工作缺工具、对别人的女仆开界面、她睡着时改设置、没人坐在棋盘对面时落子——都去做，游戏怎么回就怎么报。
