# 领域规格：吃穿与背包

> 状态：已批准（2026-10-09）。第 10 节逐项审过并直接改过：改了第 1 项（没点名时只吃普通食物和垃圾食物），其余按建议。改了的做法与实现要跟进的地方见待拍板清单第六节。
> 范围：能力 `eat`（进食）、`equip`（装备）、`drop`（丢弃），里程碑一。
> 依据：物资旧逻辑清单（v0 `dev`，`aa97940c9`）的吃（E01–E07）、装备（Q01–Q09）、丢弃（D01–D10）与取物容量（A46）条目。
> 边界：`obtain` / `gather` / `craft` 归物资域；饥饿驱动的临时吃饭任务（M6 的 LATER / SOON 插入）归战斗与生存需求域。本域只保证 `eat` 能被那个临时任务直接复用。
> 说明：第 5 节"位置"都指 v0（`dev` 分支）的文件；v1 按本规格重写，不移植这些文件。

## 2 真人怎么做

饿了想吃：翻背包找吃的，挑一个能吃的（金苹果这种吃了有别的效果的也知道自己在吃什么），拿到手上长按吃完，看饱食度上去了没有。满肚子的时候塞不下普通食物，硬吃也吃不下。没吃的就说没吃的，不会为了"吃"这个动作去现杀一头牛——那是另外一件事。

穿装备：捡到头盔就戴上；身上已经戴着同款就不再戴一遍。要卸下就腾出手把它脱下来放包里，包满了先腾地方。不知道该穿哪件时看一眼候选——只有一件合适的就直接穿，好几样不一样的才会问。

丢东西：说的哪样、丢几件，心里有数才动手，因为丢出去就捡不回来了。丢的时候朝远处开阔的地方整份一抛，不丢在脚边等两秒拾取冷却一过又被自己吸回来；原地丢了会走开几步。手上包里没那么多就如实说只有几件。

## 3 新逻辑

### 3.1 eat（进食）

```text
0 已满足     没有点名食物且已不饿（饱食度 ≥ 20）→ 直接完成，写"开始时已饱"
1 找食物     身上找（主背包、副手、随身背包——M4 的身上来源，不走世界来源）：
               点名了  → 只找这一种；找不到 → NEED_ITEM（"身上没有 minecraft:xxx"）
               没点名  → 只在普通食物里选（不带效果、饱腹时不能吃的），按饱和度与营养排序；
                         没有普通的再吃只会让人更饿的垃圾食物；珍贵的、会传送的、会中毒的
                         要点名，身上只剩这些 → NEED_ITEM 写清有哪些（决定 1）
             饱食度已满且食物不带"饱腹时也能吃"组件 → 直接结束 WRONG_TIME（附当前饥饿值），不提问
             点名的物品没有 FOOD 组件 → 结束 UNSUPPORTED（"这不是能吃的；要用它请下 use"），不提问
2 拿到手上   从背包选到主手（已在主手就不动）
3 吃         原生持续使用（M3 / 按住使用键），确认条件 = 同类物品总量减少
             使用通道被别的动作占着 → 交给 M3 的交互机会排队，不另写判断
4 结算       changes 记 item_used；吃出来的状态效果如实写进 details.effects_gained
             使用结束了数量没少 → 失败，不冒充吃饱（附当前饥饿值）；期间拾到同类食物会干扰
             这份证据，计数时把这段时间新捡到的扣除（F：拾取发生在确认窗口内）
```

本能力特有的部分只剩：食物挑选、饱腹时的原版限制、"数量减少"这个确认条件。其他全是 M3 / M4 / M8。

### 3.2 equip（装备 / 卸下）

```text
0 已满足     穿：目标栏位已经是同一件（按物品类型比，不看耐久与附魔）→ 直接完成
             卸：目标栏位本来就是空的 → 直接完成，写"开始时已卸下"
1 校验       operation 缺失或非法、unequip 没给 slot、equip 给了 armor → 参数校验阶段直接拒绝，
             不进游戏（详见第 4 节参数表）
2 找物品     穿：身上找 item（主背包 → 副手 → 随身背包）；没给 item 且该栏位候选唯一 → 自动选；
             候选是几种不同的物品 → 提问 CHOOSE_ONE（M8 ②：穿哪个后果不同），附候选列表；
             身上没有 → NEED_ITEM
             卸：不需要物品
3 腾地方     卸下要有地方放：InventorySpace.makeRoom(1, 用途=卸装备)（M5）；
             腾不动 → INVENTORY_FULL（M5 已经问过"动贵重品吗"，没被允许才走到这）
4 动手       穿：盔甲 = 拿到主手 + 对自己使用一次；副手 = 与原副手交换；主手 = 选中（M3 确认）
             卸：从栏位取下放包（容器界面的原生点击，M11 规矩）
             栏位与物品类型不匹配 → 提交前核对，不符直接结束（F：头盔进不了胸甲栏）
5 结算       穿：确认栏位内容变了才算；副手里已是完全相同的一份 → 第 0 步就结束了，不存在"换了外观不变"
             卸：逐个栏位卸；没能确认的进 unconfirmed；有栏位仍穿着 → partial，remaining 列出仍穿着的栏位
```

### 3.3 drop（丢弃）

```text
1 校验       item 和 count 必填、count 范围 → 参数校验阶段拒绝，不进游戏；"丢弃不可逆"写进能力说明
2 核对库存   背包里有多少：为 0 → NEED_ITEM；少于 count → 按实际持有的丢，结果 partial，
             remaining 写清还差几件（待拍板：决定 3）
             接单到执行之间库存变少 → 以执行时的实际持有为准（世界在变）
3 选点       朝面前远处整份抛出：找一个面前开阔、离自己几格的方向（C：玩家不会把东西丢在脚边）
             不再挖坑、不再判定"丢弃区"——v0 把开阔地判成无可丢弃区的缺陷随整条选址链删除
4 丢弃       抛掷 + 部分数量的原生分堆点击（M3 / M11 确认）；站位中途变了 → 交给 M2，余料保留
5 防捡回     原地丢弃后走出拾取范围再收场；落点登记进本会话的寻路避让（F：拾取冷却约 2 秒，
             一过就会被自己吸回；避让让后续走路不再踩进自己的丢弃堆）
6 结算       changes 逐份记 item_dropped；抛掷没等到确认 → unconfirmed（"没等到确认不等于确定没丢"，
             不得报"确定没丢"），不盲目重试
```

## 4 能力说明（参数与结果）

三个能力都不接受 `target`（吃、穿、丢都是对身上的东西做的）；可选的 `permissions` 按 M7，只有 drop 的落点避让间接相关。

### eat

| 参数 | 必填 | 说明 |
| --- | :---: | --- |
| `item` | | 要吃的物品 ID；不给时在身上能吃的里自动选 |
| `count` | | 吃几件，默认 1（"吃到饱"是生存需求的事，不是本能力的参数） |

结果细节：`effects_gained`（吃出来的状态效果列表，没效果为空）。

### equip

| 参数 | 必填 | 说明 |
| --- | :---: | --- |
| `operation` | | `equip` 穿 / `unequip` 卸 |
| `slot` | | 栏位：`mainhand` / `offhand` / `head` / `chest` / `legs` / `feet`；`armor` 只允许配合 `unequip`，表示整套卸下 |
| `item` | | 要穿的物品 ID；候选唯一时可省 |

结果细节：`still_worn`（没卸下来、仍穿着的栏位列表；只有 `operation=unequip` 且结果为 partial 时非空）。

### drop

| 参数 | 必填 | 说明 |
| --- | :---: | --- |
| `item` | ✅ | 要丢的物品 ID |
| `count` | ✅ | 要丢几件（1..999） |

结果细节：无（丢了几件在 `changes`，没确认的抛掷在 `unconfirmed`，试过什么在 `attempts`）。

## 7 游戏事实的新归属

| 事实 | 新位置 |
| --- | --- |
| 创造模式没有饥饿机制，吃普通食物不消耗 | `ability.eat` 第 1 步 |
| 饱食度满时原版不允许开始吃普通食物；带"饱腹也能吃"组件（如金苹果）的例外 | `ability.eat` 第 1 步 |
| 进食的确认 = 同类物品总量减少；确认窗口内拾取同类会干扰计数 | `ability.eat` 第 4 步 |

1. 让它吃一个面包 → 拿到手上吃完，饱食度上升，结果写明消耗与效果（无）。

9. 露天平地上让它丢一组石头 → 正常丢出，不再出现"无可丢弃区"（183）。

## 11 要留的东西与预留（`reserve`）

> 状态：已批准（2026-10-28，各项按建议）。
> 范围：角色花掉背包里的东西时哪些不能动——全仓一道关"要留的东西"，以及调用方写预留用的能力 `reserve`。挑工具、现做工具怎么用它写在挖掘与工具规格。
> 边界：许可里的 `use_rare_items` 不动，它管的是能不能走扔末影珍珠这类做法，不是哪几件东西不动；哪格方块、哪只生物能碰仍归保护判断。

### 11.1 真人怎么做

东西怎么花有分寸：主人交代过攒着的，他自己拿主意时一颗不碰；主人吩咐的活儿非用不可，他先用没交代的，不够才动攒着的，用了跟主人说一声，心里把那几件划掉；没交代的，他也只拿最便宜的边角料先用，刚取回来、手上正要用的不顺手花掉；真到要命的时候（饿得发昏、快被打死），先顾命再说。主人交代一次他就记着，不用每派一次活重说一遍。

### 11.2 新逻辑

角色花掉背包里的东西，按谁拿的主意分两种，挡法不同：

| 谁拿的主意 | 例子 | 预留的 | 正要用的 |
| --- | --- | --- | --- |
| 下令的目标要用 | 目标写着的物品（`drop`、`deposit`、`eat`、`use` 给的，`build`、`machine_build` 图纸里的方块，`machine_run` 工序的投料，`quest` 要交的）；做成所要东西非花不可的（配方原料、燃料、工作台、挖得出掉落的够格工具、弹药、交易付款、附魔的青金石） | 先用身上不留的，不够才动预留的；动了从预留里扣掉，结果里点明 | 照用：拿来多半就是为了它 |
| 角色自己做主顺手花 | 挖掘路径上的现做工具与自动挑工具、垫脚与临时方块、挖楼梯填空洞、战斗垫柱子、趁空吃一口、腾背包时存走丢掉、`deposit` 不给物品时挑哪些存 | 不用 | 不用 |

**预留**（调用方点名）：用 `reserve` 写下"身上这几样各留够几件"。

- 一直有效：跟着这个世界、这个角色存下来，重启不丢，不跟着某一个目标走。
- 只在两种情况下变：调用方用 `reserve` 改或撤；下令的目标动用了预留的，动了几件扣几件——目标开始时身上比预留多出来的那些先算作不留的，超出那部分才是动了预留。保命时动的不扣，东西还是要攒的。Mod 不替调用方判断"攒够了""用不着了"。
- 留够几件按身上的总数算，与拿东西认的"身上已有"同一口径；不写件数就是这一样全都留着；写 `#` 标签就是挂这个标签的几种加起来留够；几条重叠时都要满足。
- 身上还没有的也能先预留：攒铁时先写"铁锭留 23"，挖回来一块留一块。

**正要用的东西**（自动）：手上这件事正在拿的、上一个目标刚拿到的，再加上这次目标点名要用掉的（要交的、要放的）——要交 23 块铁的目标，路上挖石、垫脚都不动那批铁。"上一个目标"只算结果里有物品变化的目标：发一句 `chat`、设一个 `timer`、写一次 `reserve` 这类不碰背包的目标结束，不冲掉上一个目标刚拿到的。上一个目标刚拿到的是猜调用方拿来就要用，所以它只挡顺手花，不挡给下令的目标备料：刚拿了木板接着要箱子，备料正该用这批木板。

**合起来**：顺手花一样东西，身上要多于"预留的 + 正要用的"，多出来的那部分才能花。两笔各算各的、宁可多留：多留只是这一趟少花一点、慢一点，少留就是这道关要防的事。

**腾背包与存东西**：物品价值分级最高一级就是要留的东西，留够的件数腾背包时不挪不丢；只剩要留的也腾不出地方，就按 `INVENTORY_FULL` 如实结束。`deposit` 不给物品时，预留的和随身要留的东西一样留在身上。

**保命不受它拦**：吃东西按已有的口径（血不到一半、饿到不能疾跑及更急）先吃不留的，不够才动留着的，动了在 `changes` 里照实记。垫脚、垫柱子这类不开口子：走到只垫多出来的料，没有就按走不通如实说。

**挡住了要说出来**：顺手的一次花费被这道关挡住没做，就在那一次的上报里说一句，带物品和件数，例如"徒手挖：做镐要的木板预留着（留 40，身上 22）"；同一样东西一个目标里只说一次。

**以后的新花法都走这一道**：火把、搭桥、燃料……任何新的顺手花法读同一份要留的东西，不另起名单、不另立参数；生产代码不许传"什么都不留"，只有测试能用。

**为什么是预留，不是白名单或分档**：分档（"只花便宜的"）要调用方猜 Mod 里哪些算便宜，猜对了也挡不住它正在攒的便宜货，比如攒着盖房的木板。白名单要调用方事先说清哪些能花，可要花什么取决于角色半路碰上什么——挖到深板岩才要镐、爬坑才要垫块、饿了才要吃的——下令时说不全，漏一样角色就徒手磨、垫不上、饿着；何况垫脚、吃东西这些现有花法本来就是"引擎挑最便宜的，减掉要留的"，白名单要么只管做工具，全仓出现两套答案，要么连它们一起改成默认什么都不花。预留只让调用方说它自己知道的事：我在攒什么。"便宜"只决定先花哪样（废石先垫、木镐先做、普通食物先吃），不决定能不能花。

### 11.3 能力说明

新增能力 `reserve`（预留）：当场返回，不占身体，手上的活照做。

| 参数 | 说明 |
| --- | --- |
| `operation` | `set`（默认）：写下这几样各留够几件，没提到的不变；`cancel`：这几样不再留，不给 `items` 就全部撤掉 |
| `items` | `[{item, at_least}]`：`item` 是物品 ID 或 `#` 标签；`at_least` 是身上要留够的件数（1 起），不写就是这一样全都留着；`cancel` 时只看 `item` |

- 结果细节：改完以后的整份预留，每项带身上现有几件。物品 ID 不存在、标签下一件物品都没有，按 `INVALID_PARAMETER` 报并带相近的 ID。
- `observe(what="self")` 加 `reserved`：预留的每一样、留几件、身上几件；没有预留时不出现。
- 结果的 `changes` 里，用掉、放下、存走、丢掉的记录动到预留的，带 `from_reserved`（其中几件是预留的）。
- `at_least` 新登记进参数名表：身上要留够几件，只配 `reserve`；它和 `count`（这次要多做多少）不是一回事，所以不复用 `count`。
- goal 不加参数，`permissions` 不动。同步 `07-对外接口.md` 与参数名表，更新日志加一条。

### 11.5 行为变化清单

- 之前：垫脚和趁空吃绕开正要用的东西，挖楼梯填空洞、战斗垫柱子、腾背包却不绕；发一句话就冲掉"上一个目标刚拿到的"；调用方没有办法说"这些我攒着"，拿东西时身上的料不分谁留着就先用。
- 之后：角色自己做主的花费全仓只过要留的东西一道关：预留的不用、正要用的不顺手花，保命例外；下令的目标先用不留的，不够才动预留的并扣账；不碰背包的目标不冲掉上一个目标刚拿到的。
- 调用方可见的变化：新增 `reserve` 能力与 `observe(self)` 的 `reserved`；被预留挡住的顺手花费在结果里说一句；动用预留的在 `changes` 里带 `from_reserved`；挖楼梯填空洞、战斗垫柱子、腾背包不再动正要用的和预留的。

### 11.6 删除清单

生产代码不再传 `ItemsToKeep.NOTHING`：挖楼梯填空洞、战斗垫柱子换成真的要留的东西，挪到快捷栏挑格子改用只看东西本身的挑法，几处"不传就什么都不留"的便利构造删掉；`NOTHING` 只留给测试，架构检查拦住生产代码再用它。

### 11.7 验收

- 离线用例：预留的不被任何一种顺手花法动（现做工具、自动挑工具、垫脚、填空洞、垫柱子、趁空吃、腾背包、不给物品的存放）；正要用的只挡顺手花、不挡给下令的目标备料；下令的目标先用不留的、不够才动预留的，开始时多出来的先算、动了几件扣几件；保命动的不扣；标签按合计、不写件数全留、重叠的都满足；这次目标点名要用掉的（要交的铁）路上不动；不碰背包的目标结束不冲掉上一个目标刚拿到的；生产代码不传"什么都不留"（架构检查）。
- 实机：①预留「木板留 20」、包里 22 块，回露天要现做镐——最多动 2 块，不够就徒手挖并说明（与挖掘与工具规格同一场）；②预留木板 40、身上 45，`build` 一栋要 30 块木板的小屋——照放，预留剩 15，`observe(self)` 与 `changes` 的 `from_reserved` 对得上；③预留三组圆石后背包塞满——腾背包不丢那三组；④拿 3 块圆石、发一句 `chat`、再回露天——爬坑垫脚不垫那 3 块；⑤重启客户端后 `observe(self)` 里的预留还在。

### 11.8 已定

1. 预留常驻在角色身上，不做成每个目标的参数：攒料几乎总跨好几个目标（拿料、赶路、再拿、施工），挂在单个目标上，哪次忘带就失效，而且失效时没人知道，花掉以后才在结果里看见；常驻的在 `observe(self)` 里每次都给出来，LLM 不用记。旧的预留不撤会一直挡着顺手花，所以被挡住时一定说出来，下令的目标用掉了自动扣。
2. 下令的目标先用不留的，不够才动预留的并扣账。不采用"目标没写着就不动预留的"：攒料正为这件事时（打龙前留的箭、做信标留的铁块、附魔留的青金石），那样要先撤预留再下令，一来一回容易卡住。
3. 名字：能力 `reserve`、件数 `at_least`、`observe(self)` 的 `reserved`、`changes` 上的 `from_reserved`。不叫 keep：Minecraft 玩家会读成死亡不掉落。
4. "上一个目标"只算结果里有物品变化的目标。

### 11.9 09 里的名字

预留、要留的东西、正要用的东西、留够几件（`at_least`）已登记；物品价值分级最高一级改叫要留的东西。存预留的类型叫 `ReservedItems`，放哪个包实现时定。
