# 领域规格：看画面

> 状态：待批。
> 范围：LLM 按需看角色眼里此刻的画面：`observe` 加一个视图 `picture`，从游戏客户端自己的画面缓冲取一帧，图上标出看得见的观察编号，和结构化的观察对得上；给了要看的东西、角色又腾得出头来时，先转头看过去再拍。属于 M12 感知。Amaidesu 侧要改的事项单列在第 11 节，本规格不改它。
> 依据：直播里主播 Agent 一直看着直播画面（Amaidesu 每 5 秒从 OBS 取一帧）；游戏 Agent 只能调宿主的公用截图工具，它截的是桌面，直播时截到的可能是 OBS 或控制台，不一定是游戏。定下的取向：主播一直看；游戏 Agent 按需看，看的是游戏本身；Mod 自己做事读游戏数据，不看画面。现状按 `origin/dev` `01104653d` 核过，游戏事实按 Minecraft 1.21.1（NeoForge 21.1.233 的反编译源码）核过（第 7 节）。
> 边界：画面只给 LLM 看外观和找东西，不进任何判断：寻路、采集、做东西、生存需求、结果判定照旧读游戏数据。不做图像识别，不在 Mod 里调视觉模型。主播看的直播画面不归本规格。

## 1 范围

### 1.1 现状

| 方面 | 现在怎样 | 位置 |
| --- | --- | --- |
| Mod 给不给画面 | 不给。MCP 结果只有一段 JSON 文字 | `mcp.tool.ToolCatalog.wrap` |
| 游戏 Agent 看画面 | 只能调宿主的公用工具 `vision_look_at_screen`：截整块显示器，直播时可能截到 OBS、控制台、仪表盘；带着物品栏、聊天栏 | Amaidesu `src/modules/vision/look_at_screen.py` |
| 主播看画面 | 采集器每 5 秒从 OBS 节目画面取一帧，决策时挂在第一次请求尾部，不写进历史；只用于观感，数值以游戏记录为准 | Amaidesu ADR-041 |
| 宿主收到 MaiCraft 的图会怎样 | MCP 映射层认得图片内容块；但游戏 Agent 处理 `maicraft_*` 工具时直接返回原始 JSON，不经过易逝图，图会被丢掉 | Amaidesu `src/agents/minecraft/agent.py` 的 `_execute_tool` |
| 转头看东西 | 闲时看：读后看与闲看，只转头和开界面；`IdleLooking.Availability` 分 `FREE`（闲着）、`HEAD_ONLY`（主目标等回答或被暂停，只转头）、`TAKEN`（有任务或人按了 F8） | `behavior.perception.looking` |
| 看得见的东西怎么指 | `observe(scene)` 每样带观察编号 e# / f# / b# / s#，LLM 拿编号下目标 | `mcp.view.SceneView` |

### 1.2 本规格新增

- **视图 `observe(what="picture")`**：角色眼里此刻的画面，一张图加一段文字；
- **取一帧**（`game.picture`，新子包）：在世界画完、物品栏和界面还没画的那一刻，从游戏自己的画面缓冲取一份拷贝；
- **为拍画面转头**（`behavior.perception.looking.PictureLook`）：给了要看的东西、角色腾得出头时，用闲时看的那一回看转过去；
- **标注**（`mcp.view.PictureLabels`）：图上标出看得见的观察编号，文字里列出每个编号在图上的位置；
- **MCP 结果带图**：`ToolCatalog.wrap` 能在 JSON 文字后面再放一个图片内容块。

会改到的既有部分：`ObserveTool`、`ToolCatalog`、`ErrorCode`（`UNAVAILABLE` 的说明放宽到"这一次拿不到"）、`IdleLooking`、`Bootstrap`；`game.mixin` 加一个 Mixin。控制循环、目标运行表不改。

## 2 真人怎么做

玩家干活时不会停下来盯着屏幕看半天：血量、背包、聊天栏扫一眼就知道，箱子里有什么打开就看见。真要"看"的时候是这些：房子盖完退两步看看好不好看；有人说"看我这张地图"，转过去看对方手里的画；朋友在那边比划，看对方指的是哪；做完一件东西觉得哪里怪，再看一眼。看的时候转过头去看，看完回过头接着干；手上在挖矿、在跑路时不会扭头去看风景。直播间里的观众看到的就是玩家的镜头，玩家转头看什么，观众也跟着看到什么。

## 3 新逻辑

### 3.1 什么时候看画面，什么时候用结构化数据

默认不看。结构化数据精确、便宜、不会认错字；画面只回答结构化数据答不了的"看起来怎样"。

| 想知道的 | 用什么 | 为什么 |
| --- | --- | --- |
| 自己的血量、饥饿、背包、手持、装备、状态效果 | `observe(self)` | 数字精确；画面里的血条、物品栏也不在图上（3.3） |
| 周围有什么、在哪个方位、多远、是不是敌对 | `observe(scene)` | 有编号、方位、距离，能直接下目标 |
| 告示牌上的字 | `observe(scene)` 的 `signs`、`observe(detail)` | 读的是牌子上的原文，图里的小字容易认错 |
| 谁说了什么 | `events(topic=chat)` | 原话、说话的人都准；画面里的聊天栏也不在图上 |
| 箱子、界面里有什么 | `observe(menu)`、`observe(detail)` | 按物品合并好的清单 |
| 盖得对不对（每一格是不是那种方块） | `build` 的整栋比对、`design(operation=read_site)` | 逐格比，画面看不出差一格 |
| 机器连没连上、转没转 | `machine_inspect` | 读的是网络与运行状态 |
| 别的玩家冲角色做了什么动作 | 事件 `player_body_language` | 已经写清是谁、做了什么、对着哪 |
| 地形平不平、能不能走 | `observe(scene, grid=true)` | 俯视网格逐格给 |
| **建筑好不好看、像不像样**：配色、比例、屋顶顺不顺、和周围搭不搭 | `observe(picture)` | 比对只说对不对，说不出好不好看 |
| **地图、画、旗帜、展示框里摆的东西长什么样** | `observe(picture)` | 地图画的内容、旗帜的图案只能看；能结构化读出来的名字、物品先从 `scene`、`detail` 读 |
| **别的玩家在比划什么、指着哪、穿成什么样** | 事件先说了动作；要看对方指的那一处是什么样，`observe(picture)` | 动作是结构化的，"那一处长什么样"不是 |
| **做完以后看起来对不对**：田种得齐不齐、灯够不够亮的观感、机器摆得像不像图纸 | `observe(picture)` | 结果说做成了，看起来怪不怪只能看 |
| **认不出的模组界面**（`observe(menu)` 写着认不出） | `observe(picture, with_menu=true)` | 结构化读不出来时，至少看清上面写的是什么 |
| 别人说了一样东西，`scene` 里对不上（"那个红红的东西"） | 先 `scene` 找；找不到再看一眼画面 | 先便宜后贵 |
| 景色、氛围、好不好玩 | 不归游戏 Agent：主播一直看着直播画面 | 游戏 Agent 看画面是为了把事做对 |

画面里看到的数量、血量、文字不作数，以结构化数据为准；画面和结构化数据对不上时，信结构化数据，并把对不上的地方说出来。

### 3.2 从哪取图

取游戏客户端自己的画面，不截桌面，不经过 OBS：

- **取图点**：每一帧里，世界（含第一人称的手）画完、后期效果做完，物品栏、血条、聊天栏和界面还没画的那一刻，把主画面缓冲拷一份。只在有人要图的那一帧拷，平时不动。
- **拷贝走 GPU 缩小再读回**：先在显卡上把这一帧缩到长边 1280 像素，再读回内存；标注和编码离开渲染线程以后做（3.6）。直播画面就是这个窗口，读回一次不能让它卡一下，实机验收量帧时间（第 9 节）。
- **镜头记一份**：拷的同时记下这一帧镜头的位置、朝向、视野和投影，标注按它把世界里的点换成图上的像素，和图严丝合缝。

窗口和界面的几种情形：

| 情形 | 游戏怎么样 | 拍出来怎样 |
| --- | --- | --- |
| 窗口在前台 | 照常 | 照常 |
| 窗口失焦（被 OBS、控制台挡住或没焦点） | 照常画：游戏画进自己的画面缓冲，和窗口挡没挡住无关。原版失焦半秒后会打开暂停菜单，自动化拿着角色时 Mod 已经跳过这一下；人按 F8 拿着时照原版打开 | 照常；暂停菜单是界面，不进图 |
| 窗口最小化 | 窗口尺寸变成 0 时游戏不改画面缓冲的尺寸，主循环照常画、帧率不因此降（1.21.1 还没有"不活动时降帧"）；个别显卡驱动可能在最小化时停止出帧 | 一般照常；1 秒内没有新的一帧就以 `unavailable` 回，说"游戏这一秒没画出新的一帧，窗口可能最小化了"。实机验收核对。直播时窗口本来就不能最小化（OBS 会截到黑屏） |
| 开着界面（箱子、背包、聊天框、暂停菜单） | 界面在世界上面画；1.21 的界面背景模糊在画界面时才做 | 默认只拍世界，不模糊、不带界面；结果写 `menu_open` 是哪种界面。`with_menu=true` 才连界面一起拍（3.3） |
| 按了 F1 | 物品栏和手都不画 | 世界照拍，没有手 |
| 第三人称（F5） | 镜头在身后 | 拍的就是第三人称镜头，照实；`camera.first_person=false` |
| 加载世界、换维度、死亡界面 | 加载时不画世界；死亡界面后面世界照画 | 不在世界里按 `not_in_world`；加载中 1 秒没帧按 `unavailable`；死亡界面同"开着界面" |

### 3.3 带不带物品栏、聊天栏、界面

- **物品栏、血条、聊天栏、F3 调试信息、F9 调试面板：一律不带。** 这些信息全有结构化读法，而且更准（画面里的聊天栏常把字和名字认错）；F9 调试面板画的是任务内部的路线和状态，属于执行细节，不给 LLM。南瓜头、细雪、下界传送门的遮罩也画在这一层，同样不进图；失明、黑暗、水下的雾是世界的一部分，照拍。
- **不靠临时按 F1 去掉它们**：按 F1 拍一帧再按回来，直播画面会闪一下，人在操作时还会打乱人的设置。取图点本来就在物品栏之前，不用动任何设置。
- **界面默认不带，`with_menu=true` 才带**：带界面时拍的是这一帧画完以后屏幕上的整幅画面（界面、背景模糊、底下的物品栏都在）。只为一种情形开：界面开着、结构化读不出来。没开界面时给了 `with_menu`，和不给一样，结果里说一句"没有开着的界面"。

### 3.4 拍哪个方向：转不转头

```text
0 校验     id 先按 observe(detail) 的认法（观察编号、记住的地点），都不是再认建筑档案名；认不出 → unknown_id
1 能不能转 给了 id：此刻能转头才转（下面"能转头"），不能就不转，照镜头此刻拍，写明为什么没转
           没给 id：闲时看正转着头看别处、又能转头时，先转回站定朝向；否则照镜头此刻拍
2 转过去   用闲时看的那一回看，速度按读后看（每秒约 150 度），不等读后看的反应时间
           看得见的对准它：实体对准身子中间，方块与设施对准那一格，地形特征与建筑对准外框中心
           看不见的只朝大致方位瞥（与读后看同一条，不让观众以为角色在透视）
           最多等 2 秒转到位；到不了就拍此刻的，写"没转到位"
3 等一帧   到位后等下一帧画完再取（镜头插值走完）
4 取图     第 3.2 节
5 标注     第 3.5、3.6 节
6 回       图加文字，observe 当场返回
7 收尾     镜头在那儿停够 0.8 秒，转回站定朝向（闲时看照常往下走）
           其间来了新目标或临时任务，闲时看当刻收手，任务自己转头
```

**能转头**：闲时看此刻是 `FREE`（闲着）或 `HEAD_ONLY`（主目标在等回答、被暂停），并且闲时看"只转头"的那几条都满足：脚踏实地、没骑着坐着、没在睡没在飞、屏幕上没有别人开的界面、背包已经同步。实例配置 `idleLooking` 关着也转：那个开关管的是演给观众看的闲看，这里是 LLM 要看。

**手上有活时不转头**（`TAKEN`）：照镜头此刻拍，`toward.turned=false`，`not_turned_because` 写"手上在做「…」，转头会带歪它的瞄准和走路；要转过去看，先 goal(pause) 这个目标，看完 resume"。理由：

- 走路、挖方块、放方块都按镜头朝向结算，扭一下头，这一格就挖歪、路就重算；
- 要停下手上的活才能转头的事，在 LLM 手里有现成的做法（暂停、看、恢复），不用 Mod 替它决定停不停；
- 干活时要看的多半就是手上这件事，镜头本来就对着它。

不做成"插一下"（`CUTS_IN`）：插一下是目标，`execute` 只回 `goal_id`，图要等目标做完再取，看一眼变成三次调用；它还会让一次 `observe` 暂停手上的任务，`observe` 就不再是只看不做（第 10 节第 4 项）。

**骑着、坐着、在飞、在睡、人按 F8 拿着角色、屏幕上开着别人的界面**：都不转，照镜头此刻拍，写明原因。骑马时马跟着视角转身，鞘翅靠视角操纵；人按 F8 时鼠标在人手里，拍的就是人正看着的。

**截完转不转回去**：转回，但不立刻甩回。停够 0.8 秒（读后看看一样东西的最短时间），再按闲时看的规矩慢慢转回站定朝向。观众看到的是"角色转头看了一眼那边，又转回来"；拍完立刻甩回去，在直播画面上就是一下抽搐。站定朝向一直保住：转头期间和转回之前，观察的前后左右、方向目标的"往前"都还按转头前的朝向算，LLM 看完画面下的"往前 20 格"不会走歪。

**不为看一眼走路**：离得太近装不下、隔着东西看不见，都照实说（3.5 的 `framed`），要走过去、退几步由 LLM 用 `travel` 去。和闲时看"不为看一眼走过去"是同一条。

### 3.5 图上的编号和画面怎么对上

图上标出看得见的观察编号，文字里再列一遍每个编号在图上的位置。这样模型看到图里"那个人""那只箱子"，就知道它是 `e4`、`b5`，可以直接拿来下目标，不用自己猜哪个是哪个。

**标哪些**：这一刻场景里看得见的条目（实体、设施、告示牌、地形特征、模组的东西），落在画面里、在镜头前面的。看不见的不标：标了就等于把墙后的东西画到墙上，既是透视，也会让模型以为那里有东西。

**遮挡**：按镜头所在点到条目的视线判断，用感知判断"看见"的同一份视线，只把起点换成镜头。第一人称时镜头就是眼睛，结果和场景里的 `visible` 一样；第三人称时以镜头为准。实体先试身子中间，挡住了再试头顶，有一点看得见就标在那一点；方块、设施标在那一格朝镜头的那一面上；地形特征、建筑标在外框里看得见的那一点。

**样式**：

- 小标签：深色半透明底、白字，写编号本身（`e4`、`b5`、`f3`），不写名字（玩家头顶本来就有名牌）；边框颜色按种类分：实体黄、设施与告示牌青、地形特征绿、模组的东西紫；
- 标签放在那一点正上方，下边一个小尖角指着那一点；字高约为图高的四十分之一（720 高时约 18 像素）；
- `id` 指的那样东西边框加粗；其他标签不压进它在图上的外框，它占了大半个画面时不管。

**挤的时候**：按先后摆：`id` 指的那样东西 > 玩家 > 敌对生物 > 设施与告示牌 > 其他实体 > 地形特征；同一档近的先。每个标签先试正上方，压到已经摆好的就依次试右、左、下，再往上挪，最多挪三个标签高；还放不下就不标，文字里照列，写 `labeled=false`。图上最多标 24 个，多的同样只列不标。不标不是删：每个看得见的编号都在 `in_picture` 里，带图上的位置。

**不标的图**：看外观（建筑好不好看）时标签会挡住东西，`unlabeled=true` 出一张不带标注的图；`in_picture` 照样列编号和位置。

标注只画在交给 LLM 的那份拷贝上，直播画面上不出现。

### 3.6 返回什么

MCP 调用结果里两个内容块：先是和别的视图一样的 JSON 文字，再是一张 JPEG（MCP 的图片内容块，`mimeType` 为 `image/jpeg`）。不支持图片的宿主照样能读文字那一块。图的 base64 不进 JSON。

```json
{
  "picture": { "width": 1280, "height": 720, "format": "image/jpeg", "labeled": true, "menu_included": false },
  "camera": { "direction": "前方偏右", "compass": "东北", "pitch": "略向下", "first_person": true },
  "toward": { "id": "小木屋", "turned": true, "framed": "partly", "step_back_blocks": 6 },
  "in_picture": [
    { "id": "e4", "type": "minecraft:player", "name": "Alex", "at": [902, 410], "labeled": true },
    { "id": "b5", "block": "minecraft:chest", "at": [214, 560], "labeled": true },
    { "id": "f2", "kind": "tree_cluster", "at": [1150, 260], "labeled": true },
    { "id": "e9", "type": "minecraft:item", "at": [930, 600], "labeled": false, "not_labeled_because": "太挤" }
  ],
  "menu_open": "storage",
  "summary": "转过去看建筑「小木屋」，只装进一部分，往后退约 6 格能装下；画面里看得见 4 个编号，标了 3 个；开着箱子界面，没拍进去。"
}
```

- `camera`：拍下这一帧时镜头朝哪。`direction` 是相对站定朝向的方位（和场景里的 `direction` 同一套词），`compass` 是东南西北，`pitch` 是平视 / 略向上 / 向上 / 略向下 / 向下。
- `toward`：只在给了 `id` 时有。`turned` 转没转过去；没转时 `not_turned_because` 一句话；`framed`：`whole` 整个在画面里，`partly` 只拍到一部分，`hidden` 隔着东西看不见；`partly` 时 `step_back_blocks` 是按此刻的视野往后退约几格能整个装下（实体不算这一项）。
- `in_picture`：画面里看得见的每个编号，`at` 是它在图上的像素位置 `[x, y]`（从左上角量）；种类字段与场景同名（实体 `type`，玩家另带 `name`；设施与告示牌 `block`；地形特征 `kind`；模组的东西 `category`），方位、距离不重复，要看去 `scene`、`detail`。
- `menu_open`：开着界面时是哪种，取值同 `observe(menu)` 的 `kind`；没开不带。
- `summary`：一句话，说转没转、装没装下、标了几个、有没有界面没拍进去。

**图的尺寸**：长边 1280 像素，按窗口的宽高比，JPEG 质量 85，单张约 100 到 250 KB。不给 LLM 调尺寸：要看清远处的小东西，走近比放大有用。

**限流（Mod 这边只管不拖慢游戏）**：同一时刻只拍一张；两次之间至少隔 1 秒，再快按 `busy` 回，说"上一张刚拍完，1 秒后再拍"。一个任务里看几次、多久看一次是宿主的成本问题，归宿主管（第 11 节）：别的宿主、别的模型价钱不一样，Mod 不替它们定额度。

**不进记忆**：画面不写进世界记忆，也不进事件和目标结果；拍这一下会像 `observe(scene)` 那样先刷新一次场景，新看见的东西照常拿到编号。

### 3.7 接口形状：为什么是 `observe` 的一个视图

| 做法 | 好处 | 问题 |
| --- | --- | --- |
| **`observe(what="picture")`**（建议） | `observe` 本来就是"玩家此刻能看见什么"，画面就是字面意思上的这件事；当场返回，一次调用拿到图；不进目标，不碰手上的任务；LLM 已经熟悉 `observe` 的 `id` | `observe` 的参数多两个只在 `picture` 用的字段 |
| 新的只读能力（`execute` 当场返回报告） | 能力目录里看得到 | 能力是"一个有完成标准的意图"，看一眼不是；结果是 JSON 报告，要另开一条路把图塞进 `execute` 的回复；只读能力还会触发读后看，和这里的转头重复 |
| 单独的 MCP 工具 | 参数干净 | 多一个工具，和 `observe` 抢"看"这件事；LLM 要多分辨一次该调哪个 |

**怎么让宿主知道**：`picture` 是 `observe` 的一个视图，不是能力，不出现在 `lookup()` 的能力列表里。宿主从 MCP 的工具列表里读 `observe` 的说明就知道有它（宿主连上时本来就读）。旧版 Mod 不认 `picture`，`observe(what="picture")` 按 `invalid_parameter` 回并列出能选的视图，宿主照这个判断就行，不另加握手字段。

`observe` 的说明加的话（宿主中立）：

> `picture`：角色眼里此刻的画面（一张图），只拍游戏世界，不带物品栏、血条、聊天栏；图上标着看得见的观察编号，文字里列出每个编号在图上的位置。看外观、看地图和画、看别人比划的那一处时用；数量、血量、背包、聊天、告示牌的字以 `self`、`scene`、`detail`、`events` 为准。给 `id` 时角色闲着就先转头看过去再拍，手上有活时不转头。

字段说明：

| 字段 | 说明 |
| --- | --- |
| `id` | 只在 `what=detail` 或 `picture` 时用：观察编号（`e12`、`f3`、`b5`、`s2`）或地标名；`picture` 还收建筑档案名（转过去看那一栋） |
| `with_menu` | 只在 `what=picture` 时用：`true` 时连同此刻开着的界面一起拍（整幅屏幕画面）；界面认不出、结构化读不出来时用 |
| `unlabeled` | 只在 `what=picture` 时用：`true` 时图上不标观察编号（看外观时用）；编号和它们在图上的位置照样列在 `in_picture` |

`id` 不收坐标：`observe` 的 `id` 一直是"编号或名字"，加坐标要再开三个字段；要看一处坐标，先 `remember` 成地点再用名字，或者走过去（第 10 节第 7 项）。

### 3.8 组合了哪些模型，代码放哪

组合：M12 感知（看得见的条目、观察编号、方位说法、视线）、闲时看（一回看、站定朝向、能不能只转头）、M9 世界记忆（地标名）、建筑档案（`id` 是档案名时那一栋的外框）。

| 放哪 | 是什么 |
| --- | --- |
| `game.picture`（新子包） | `CameraPictures`：收"要一幅画面"的请求，在取图点拷一份、缩小、读回，交给请求线程；`CameraPicture`：像素、宽高、拍下那一刻的镜头（位置、朝向、视野、投影），能把世界里一点换成图上的像素、说出那一点在不在镜头前面。只读，不改任何设置 |
| `game.mixin.GameRendererPictureMixin`（新） | 在 `GameRenderer.render` 里世界画完、物品栏画之前调 `CameraPictures`；`with_menu` 的请求在这一帧画完以后取 |
| `behavior.perception.looking.PictureLook`（新） | 为拍画面转头：能不能转（纯函数，读闲时看的 `Availability` 与"只转头"的几条），转得了就交闲时看做那一回看并报告到位了没有；`IdleLooking` 加接这种请求，开关关着也接 |
| `mcp.view.PictureView`（新） | 整理 `in_picture`、`toward`、`camera`、`summary`；`PictureLabels`（纯函数：标哪些、按什么先后、摆在哪、挤了不标哪些）；`PictureFraming`（纯函数：整个在不在画面里、往后退几格能装下） |
| `mcp.view.PictureEncoding`（新） | 在请求线程上画标注、编 JPEG；用 Java 自带的二维绘图和图像编码，不在渲染线程上做 |
| `mcp.tool.ObserveTool`、`ToolCatalog` | 加 `picture` 视图与两个字段；`wrap` 能带图片内容块。`id` 是建筑档案名时经 `ability.design.api.BuildingRecords` 按名字找那一栋（同名的几栋不在一处时按 `unknown_id` 回，说清有几处、让 LLM 改用编号），取它的范围当外框 |
| `mcp.tool.ErrorCode` | `UNAVAILABLE` 的说明放宽成"要的东西这一次拿不到"，画面没出帧也用它 |

切子包：`game.picture` 是"从客户端自己的画面缓冲取画面"一件事，和 `game.world`（读世界）、`game.player`（读写角色）都不是一回事，调用方只有 `mcp` 的 `observe`。标注和取景放在 `mcp.view`：它们只决定 LLM 看到的形状，此刻只有 `observe(picture)` 一个调用方，不提前下沉到感知。转头放在闲时看：全仓转头看东西只有这一份，"能不能只转头"也已经在那里。

## 9 验收

### 离线测试

- `PictureLabels`：只标看得见、在画面里、在镜头前面的；先后顺序（`id` 指的 > 玩家 > 敌对 > 设施与告示牌 > 其他实体 > 地形特征，同档近的先）；压到别的标签依次试右、左、下、往上挪，放不下的 `labeled=false` 且仍在 `in_picture`；最多 24 个；不压进 `id` 指的那样东西的外框，它占大半个画面时不管；`unlabeled` 时一个不画、列表照给。
- `PictureFraming`：整个在、部分在、看不见三种；部分在时往后退几格的算法对得上视野；实体不给后退格数。
- `CameraPicture` 的投影：拍下那一刻的镜头把世界里已知的点换成像素，和渲染用的投影一致；镜头后面的点报不在镜头前面。
- `PictureLook`：`FREE`、`HEAD_ONLY` 时能转，`TAKEN` 不转并给原因；骑着、在飞、人按 F8、别人开着界面时不转；`idleLooking` 关着也能转；看不见的只朝大致方位；2 秒没到位按没到位拍；拍完停 0.8 秒再交回闲时看。
- `ObserveTool`：`id` 只在 `detail`、`picture` 收；`with_menu`、`unlabeled` 只在 `picture` 收；建筑档案名能认；认不出的 `id` 按 `unknown_id`；正在拍时再来一张按 `busy`；1 秒内没帧按 `unavailable`。
- `ToolCatalog.wrap`：带图时两个内容块，先文字后图片，图片块 `mimeType` 是 `image/jpeg`；JSON 里没有 base64。
- 接口快照更新；架构检查照过；新名字登记 09。

### 实机验收

1. 闲着时 `observe(picture)`：拿到一张没有物品栏、血条、聊天栏的游戏画面，编号标在对的东西上；直播画面没闪、没出现标注。
2. 闲着时 `observe(picture, id=…)`，分别给玩家的 e#、箱子的 b#、树林的 f#、刚盖完的建筑档案名：角色转过去、拍到的对准它、停一下再转回来；离建筑太近时 `framed=partly`，按 `step_back_blocks` 退过去再拍能整栋装下。
3. 角色在挖矿、走路时 `observe(picture, id=…)`：不转头，结果说明没转和怎么办；`goal(pause)` 以后再拍会转过去，`resume` 后接着干。
4. 骑着马、人按着 F8 时给 id：不转头。
5. 开着箱子时拍：默认只有世界，`menu_open=storage`；`with_menu=true` 拍到界面。
6. 游戏窗口被 OBS 挡住、没有焦点时拍：照常拍到游戏画面。
7. 游戏窗口最小化时拍：记下这台机器上拍不拍得到（拍不到时是 `unavailable`、说得清原因）。
8. 隔着墙的箱子、墙后的生物：图上没有它们的标签。
9. 1 秒内连拍：第二张 `busy`；隔 1 秒连拍 10 张，直播画面没有可见的卡顿（帧时间没有明显尖峰）。
10. 第三人称时拍：`first_person=false`，标签仍落在对的东西上。
11. 宿主两条路（第 11 节）：能看图的模型看到了图，历史里只留文字；不能看图的模型拿到转成文字的描述。

只列要做什么，怎么做由那边定。Mod 侧实现并推 `dev` 之后再开工，字段以 07 为准。

1. **接住 MaiCraft 返回的图**：游戏 Agent 执行 `maicraft_*` 工具时现在直接返回原始 JSON，图片内容块被丢掉。改成：文字那一块照旧当观察写进历史，图片块交给易逝图，只挂在下一次请求尾部，用完即弃，不进历史。上个任务没用上的图不带进新任务（现在已经这样）。
2. **模型不能看图时**：经现有的视觉模型转文字，问题按这次调用拼：看的是哪个编号、画面里标了哪些编号，请说清画面里有什么、各个编号的东西看起来怎样、有没有不对劲的地方。转出来的文字接在观察后面；转失败时只给文字那一块，说一句"画面没能转成文字"。
3. **次数与间隔**：建议同一个委派任务里最多看 6 次，两次之间至少隔 10 秒；超了不调 Mod，直接回一句"这个任务已经看了 6 次画面，接下来用 observe 的结构化数据"。数字按实际花费调。
4. **游戏 Agent 提示词**：
   - 默认不看画面。能用 `self`、`scene`、`detail`、`menu`、`events`、目标结果回答的，不看；
   - 值得看的：盖完的建筑好不好看、地图和画上是什么、别人比划的那一处、做完的东西看起来对不对、认不出的模组界面（`with_menu=true`）；
   - 画面里的数量、血量、文字不作数；和结构化数据对不上时信结构化数据，并说出来；
   - 图上的编号就是观察编号，可以直接拿来下目标；
   - 要看全一栋房子，先站到装得下的地方（结果的 `step_back_blocks`），再给 `id` 拍；手上有活时不会转头，要转过去看先暂停目标，看完恢复；
   - 看完要记住的内容写进自己这一步的话里：图只在下一次请求里可见；
   - 现有的"截图里的聊天栏容易认错字和名字"一句改成"谁说了什么以 `events(topic=chat)` 和主播转来的原话为准"。
5. **截桌面的 `vision_look_at_screen` 对游戏 Agent 撤掉**：它截的是整块显示器，直播时多半是 OBS 或控制台，还带着聊天栏和别的窗口，不一定是游戏。别的 Agent（文字冒险等）照旧用。
6. **主播派活不用画面上的方位指东西**：主播看的是几秒前的直播画面，带着物品栏，游戏 Agent 的镜头这时可能已经转开，"画面左边那个""屏幕上方那个"它对不上。派活和补充要求里写清意图和特征：是什么、什么颜色、多大、在什么旁边、是谁的；说得出名字、地点名的说名字。主播派活规则提示词里加一条。
7. **主播不调 `observe(picture)`**：主播已经一直看着直播画面；主播的"看一眼游戏"照旧只读结构化数据。
8. **图不进事件流和诊断记录**：`maicraft_observe` 的工具结果事件、诊断回放里只记文字和"带了一张图"，不记 base64（和截图工具同一条）。

## 需登记 09 的新名字

| 中文 | 代码 / MCP | 意思 |
| --- | --- | --- |
| 画面 | 观察视图 `observe(what="picture")`；`mcp.view.PictureView` | 角色眼里此刻的画面：从游戏自己的画面缓冲取的一帧，只有世界，不带物品栏、聊天栏；不叫 screenshot（会被读成截桌面、存进截图文件夹），不叫 view（会和"观察视图"一词两义），不叫 screen（Minecraft 代码里 screen 是界面） |
| 取画面 | `game.picture.CameraPictures`、`CameraPicture` | 在世界画完、物品栏画之前拷一份主画面缓冲，连同那一刻的镜头；只读，不改设置 |
| 为拍画面转头 | `behavior.perception.looking.PictureLook` | 给了要看的东西、角色闲着或主目标在等回答被暂停时，用闲时看的一回看转过去再拍；手上有活时不转 |
| 画面标注 | `mcp.view.PictureLabels`；字段 `unlabeled`、`in_picture`、`labeled` | 图上标出看得见的观察编号，文字里列出每个编号在图上的位置；挤的不标，照样列 |
| 取景 | `mcp.view.PictureFraming`；字段 `toward`、`framed`、`step_back_blocks` | 要看的那样东西整个在不在画面里、往后退几格能装下 |
| 连界面一起拍 | 字段 `with_menu` | 连同此刻开着的界面一起拍整幅屏幕画面 |
