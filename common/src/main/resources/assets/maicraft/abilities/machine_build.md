按机器蓝图在 target 处建一台机器：蓝图落到锚点、逐格施工（缺料自己拿、挡着的挖掉、够不着垫临时方块）、装安装段与部件、改装后设置，建成后记进机器档案。target 是锚点（坐标、脚下、观察编号或记过的地点）；流体（水源、岩浆源）在实心格之后倒，同一层按 cells 里写的先后倒。target 指已有档案的名字就是修改——blueprint 是补丁，新声明的格覆盖同位旧目标，范围外旧目标保留，照档案锚点合并施工。operation=remove 拆档案里的整台，target 指档案名，逐格挖掉 cells 里的格和安装段自己放下的（机械臂、ME 线缆），安装段连到的另一头（链条另一台、机械臂取放点）不拆；档案标为已拆除（蓝图保留，随时可以照着再建）。

## 在组装好的船上施工

target 给物理结构 `s#`，或已经跟到船上的机器档案名，就是在停稳的船上施工：偏移按结构局部坐标写（和 `machine_inspect(s#)` 的 `local` 同一套：船上跟着机器档案时原点是档案锚点，造船时蓝图的偏移照用；没有档案是物理组装器）。船上已经跟着档案就把补丁并进去，没有就按 `name` 新建一份记在船上。

- 船在动先等它停稳，等 10 秒还在动就照实结束、一格不动；施工中被撞动、被风吹动就停手，结果写明动了、做到哪。
- 角色会上船或站到船边够得着的地方去放、去挖；挖方块先站船上（站在地上挖会把船推一下）。够不着的照实写，不拆船、不往船上垫临时方块。
- 放、挖、扳手转向、补胶（强力胶、蜂蜜胶）在船上会；别的安装段、部件、装后设置、倒桶写明"结构上还不会"，要做先拆回。
- 加配重：`machine_inspect(s#, balance=ballast)` 看建议的局部坐标，在这里补铁块，补完 `balance=forces` 再看受力。
- 最后一块拆光了船就没了，档案标成已拆除。

## 参数

- `blueprint` / `design_id` 二选一：机器蓝图正文（cells 逐格、parts 部件、installations 安装段 `{kind, offsets, roles}`、settings 装后设置）或已保存的设计编号；写错的地方一次报全，不进游戏。
- 安装段与部件怎么写随模组不同（传送带两端写轴、链条写两台、机械合成器连入口写相邻两台、铺轨写两端的轨道、ME 线缆写成一段、终端装在线缆的某一面、蜂蜜胶 `simulated:honey_glue` 写两个对角且角不用是方块），先 lookup 查那种机器的资料（machine/create/index、machine/ae2/index、machine/mekanism/index）。安装段格上写了方块的（例如传送带两端的轴）先照常放好，再用模组自己的方式装段；压在安装段上的格（带漏斗、隧道压在传送带上）照常写进 cells，装完安装段再放。roles 可选，和 offsets 一一对应，说每一格在这一段里干什么（机械臂的取放点写 take 或 deposit），用不着的安装段不写。
- 整台机器里某种方块的个数有上限（实例配置，默认链条输送机一台机器一个）：超了在下达时就说清。
- `name`：新机器的档案名；不给就按锚点起"机器@x,y,z"。修改已有档案时不用给。
- `operation`：`build`（默认）或 `remove`。

## 改完收拾现场

换方案、改版、试错之后，新蓝图不再用的旧东西要顺手收拾掉，别在机器旁边留一大片烂摊子：
多出来的传动杆和齿轮箱、试过不要的部件、垫脚的柱子、改线留下的旧带子。

- 整台不用的旧机器：`operation=remove` 按档案拆掉。
- 同一台里不要的零件：在补丁里把那几格写成 `minecraft:air` 拆掉。补丁范围外的旧目标默认保留，不写空气不会自己拆。
- 不在档案里的零散方块：交给 `build`，`cells` 里写 `minecraft:air` 一次清掉。
- 拆之前先用 `machine_inspect` 看那几格还连没连着正在用的机器（传动、漏斗、溜槽），连着的不动；
  拆完用 `machine_run` 或 `machine_inspect` 确认机器照样转、照样出货。拆下来还能用的料用 `deposit` 存回去。

## 结果怎么读

- 动作成没成（`changes` / `unconfirmed`）、结构对不对（`check`）分开给；机器能不能转不在这里判，用 machine_run 试或 machine_inspect 看读数。
- `check`：整机比对各结论几格；有格没加载时 `check_complete` 为假，不给"整机一致"的结论。
- 在船上施工时多 `structure`（哪个 `s#`）与 `local_origin`（局部坐标的原点是哪一格），不给 `anchor`；`changes`、安装段与部件的格都写局部坐标。
- `installations[]`、`parts[]`、`settings[]`：每段、每个、每条各自做成没有，没做成的带原因；安装段与部件占的格由机器按最终结构核对，不冒充逐格放好。
- 连链条输送机：角色连之前先手持锁链潜行对着空处按一下右键，清掉上一回没连完、Create 还记着的接线起点；点过第一台没连成也再清一次。清掉了 `changes` 里记一笔，清不掉（身上没有锁链、四下都够得着东西）时原因里写明手上的锁链还带着起点、第一下点的是哪一台——这时下一次手持锁链点链条输送机会先连到它。
- 施工子任务失败按它的问题结束，已放的不回滚；补丁已并入档案（存不进档案只记问题，不影响施工）。
- 开始时就已经和蓝图一致 → 完成，一个动作都不做。

## 问题种类

- `INVALID_PARAMETER`：蓝图或参数写法不对，一次报全。
- `NEED_APPROVAL`：有格是玩家的东西或在别人的地盘里，没动；同意拆改把 change_blocks 设为 any 再来一次。
- `NEED_ITEM`：材料用完了，拿到后再下达一次会从没建完的地方接着做。
- `UNREACHABLE`：有格够不着，或档案在另一个维度。
- `STUCK`：在船上施工时船一直在动没停稳，或施工中动起来了。
- `TARGET_GONE`：指的船不在附近看不到，或施工中船没了。
- `UNSUPPORTED`：安装段、部件或设置没有登记的机器联动认领；装了对应模组的联动后再来一次。
